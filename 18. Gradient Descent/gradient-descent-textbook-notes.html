Gradient Descent

The general-purpose optimizer that trains almost every model that doesn't have an exact closed-form solution — Linear Regression's Normal Equation is the exception, not the rule. Iteratively nudge every parameter in the direction that most reduces a cost function, using nothing but the local slope at the current point.

1.Optimization, Framed Precisely

θ* = argmin_θ J(θ) Find the parameter vector θ (e.g. [β₀, β₁, …]) that minimizes a cost function J. "Fitting a model" is this statement, for every model in this course that doesn't have a closed-form shortcut.

For Linear Regression with squared error, J(θ) is a smooth, convex bowl — a single global minimum, approachable from any starting point. That convexity is what makes Gradient Descent provably converge to the right answer here; it is not guaranteed in general (Section 9).

2.The Update Rule

θ ← θ − α · ∇J(θ) ∇J(θ) — the gradient, a vector of partial derivatives, one per parameter, pointing in the direction of steepest increase. α — the learning rate, scaling the step size. Subtracting (not adding) the gradient is what makes this descent.
  1. Initialize θ (zeros, or small random values).
  2. Compute ∇J(θ) at the current θ.
  3. Update every parameter simultaneously: θ ← θ − α∇J(θ).
  4. Repeat until a convergence criterion is met (Section 7).

3.Deriving the Gradient (Linear Regression)

For J(β) = (1/n)Σ(yᵢ − ŷᵢ)² with ŷᵢ = β₀ + β₁xᵢ:

∂J/∂β₀ = −(2/n)Σ(yᵢ−ŷᵢ)     ∂J/∂β₁ = −(2/n)Σ(yᵢ−ŷᵢ)xᵢ Both derived from one calculus fact: the derivative of (something)² is 2×(something)×(derivative of that something). β₀ shifts every prediction equally (no xᵢ factor); β₁'s shift is proportional to xᵢ, so its gradient carries an extra xᵢ term. With p features, the pattern extends to one gradient term per feature: ∂J/∂βₖ = −(2/n)Σ(yᵢ−ŷᵢ)xᵢₖ.

In vector form, for design matrix X and target y: ∇J(β) = −(2/n) Xᵀ(y − Xβ) — the same "mistake × x" shape, expressed for every parameter at once.

5.The Learning Rate

α controls step size, and picking it is mostly empirical — but the failure modes are predictable:

  • Too small — convergence is correct but painfully slow; many more iterations than necessary.
  • Too large — each step can overshoot the minimum so badly the cost increases — divergence, cost exploding toward infinity instead of shrinking.
  • Learning rate schedules — start large (fast early progress) and shrink α over iterations (fine-tuned settling near the minimum) — a common practical refinement not required for convex problems like Linear/Logistic Regression, but standard in deep learning.

6.Why Feature Scaling Matters

Geometrically: unscaled features (one ranging 0–1, another 0–100,000) stretch the cost bowl into a narrow, elongated ravine. Gradient descent then has to take tiny, cautious steps along the steep direction while crawling along the shallow one — the same step size can't be right for both at once.

Formally, this is the condition number of the Hessian (curvature matrix) of J — a bowl with very different curvature in different directions has a high condition number, and gradient descent's convergence rate degrades directly with it. Standardizing every feature (zero mean, unit variance) makes the bowl closer to circular, dramatically improving convergence speed — this is why every session from Polynomial Regression onward treats scaling as mandatory, not optional.

7.Convergence Criteria

  • Gradient norm ≈ 0 — ‖∇J(θ)‖ below a small threshold; the surface is essentially flat in every direction.
  • Cost plateau — |J(θₜ) − J(θₜ₋₁)| below a small threshold; further steps aren't meaningfully improving the fit.
  • Max iterations — a hard cap, always set, so training terminates even if the other two never quite trigger.

8.Beyond Vanilla GD

Not covered hands-on in this course, but worth knowing exist: Momentum (accumulate a running average of past gradients, so the optimizer keeps moving through small local bumps and dampens oscillation), RMSProp and Adam (adapt the effective learning rate per-parameter, based on the recent history of that parameter's own gradients). Adam in particular is the default optimizer in most modern deep learning — a more sophisticated descendant of exactly the update rule in Section 2.

9.Convex vs. Non-Convex Landscapes

Linear Regression's squared-error cost is provably convex (Section 1) — one global minimum, reachable from any starting point, which is exactly why it's the right place to learn gradient descent: the answer can always be checked against the exact Normal Equation solution. Logistic Regression's log loss is also convex (see that reference's derivation). Neural networks are not — their cost landscapes have many local minima and saddle points, and gradient descent (with momentum/Adam, mini-batching, and a lot of engineering) finds a good minimum in practice, with no guarantee it's the global one.

10.Worked Example

import numpy as np

def gradient_descent(X, y, lr=0.01, n_iter=1000):
    n, p = X.shape
    X_b = np.c_[np.ones(n), X]        # prepend intercept column
    beta = np.zeros(p + 1)
    for _ in range(n_iter):
        y_pred = X_b @ beta
        gradient = -(2 / n) * X_b.T @ (y - y_pred)
        beta -= lr * gradient
    return beta

11.Summary

The whole idea, in one paragraph

Gradient Descent repeats one update, θ ← θ − α∇J(θ), until the gradient flattens to near zero. For Linear and Logistic Regression the cost surface is a single convex bowl, so this always converges to the true minimum — the same guarantee doesn't hold for the non-convex landscapes of deep learning, where the same update rule (usually wrapped in Adam or a similar adaptive variant) finds a good-enough minimum instead. Feature scaling and the learning rate are the two levers that separate a fast, clean convergence from a slow or divergent one.
