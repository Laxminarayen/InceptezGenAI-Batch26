Hour 1 · Giving the S-Curve a Formula

Meet the sigmoid function

σ(z) = 1 / (1 + e^−z)
Feed it ANY real number z — negative, zero, huge, tiny — and it always hands back a number strictly between 0 and 1. That's the whole trick.

Watch z get passed through the formula, one arithmetic step at a time:

1

Start with z

z = 0.00

2

Flip its sign, put it in the exponent

e^−z = e^0.00 = 1.000

3

Add 1, then take the reciprocal

σ(z) = 1 / (1 + 1.000) = 0.500

σ(z) — the final probability

Hour 1 · The Logistic Regression Hypothesis

Same ruler as always, wrapped in σ

Don't throw away the straight line — reuse it. Compute z EXACTLY the way linear regression always has, then pass that single number through the sigmoid to squash it into a valid probability.

1

Step 1 — the familiar part

z = β₀ + β₁·x  (any real number, same as every linear model this whole course)

2

Step 2 — the new part

p = σ(z) = 1 / (1 + e^−z)  — now p is guaranteed to sit between 0 and 1, always.

3

Worked example — an applicant at credit index x = 6

Say fitting gave us β₀ = −4, β₁ = 0.8. Then z = −4 + 0.8×6 = 0.8, and p = σ(0.8) = 1/(1+e^−0.8) ≈ 0.690 — a 69% predicted chance of approval.

🎯 That's the entire hypothesis function: hₚ(x) = σ(β₀ + β₁x). One extra step bolted onto everything you already know.
Hour 1 · Turning a Probability Into a Decision

Where does p cross 50%?

A probability alone isn't a decision — you still need a rule. The standard one: predict APPROVE if p ≥ 0.5, else REJECT. Because σ(z) = 0.5 exactly when z = 0, that rule collapses to something wonderfully simple.

Hour 1 · Where σ(z) Actually Comes From

A real number, turned into odds, turned into p

z isn't just "a number we feed the formula" — z IS the log-odds, by definition. Drag it and watch it travel: undo the log to get odds, then convert odds into a probability. This pipeline, done in one line, is the sigmoid formula.

1

z is the log-odds — any real number

z = 0.00  (negative, zero, positive — all valid)

2

Undo the log: odds = e^z

odds = e^0.00 = 1.000  (always positive — that's what makes odds "odds")

3

Odds → probability: p = odds/(1+odds)

p = 1.000 / (1 + 1.000) = 0.500

p via the odds pipeline
0.500
σ(z), computed directly
0.500
✨ Same number, every time: odds/(1+odds) = e^z/(1+e^z) = 1/(1+e^−z) = σ(z). Sigmoid isn't an arbitrary curve — it's "log-odds → odds → probability," collapsed into one formula. That's also why β₁ has a clean reading: "each extra point of credit index adds 0.8 to the log-odds of approval."

The exact same S-curve from the last slide — now traced out by the odds pipeline instead of the raw formula.

Gradient descent found the best β's for a straight line by walking downhill on a cost function. Can we reuse the exact same optimizer here? Almost — but the cost function itself needs to change first, and there's a very good reason why.

Hour 2 · A 60-Second Recap

The five steps, still true here

🎲

1. Start with a guess

Every β starts at 0 (or any starting point).

🦶

2. Feel the slope

Work out how the cost would change if you nudged each β.

➖

3. Subtract it

new β = old β − (learning rate) × slope, for every β.

🔁

4. Repeat

Go back to step 2 with the new numbers, over and over.

🏁

5. Stop when flat

Slope ≈ 0 in every direction means you've reached the bottom.

❓

The missing piece

"The bottom" of WHAT bowl? We never actually said what "cost" means for a classifier. That's today's real question.

👀 Obvious guess: reuse Mean Squared Error, the same cost linear regression always used. Let's try it — and watch it go wrong.
Hour 2 · A Tempting Mistake

Squared error + sigmoid = a bumpy bowl

Gradient descent only works reliably when the cost surface is one smooth bowl with a single bottom. Plug σ(z) into the familiar MSE formula and the bowl stops being smooth — it grows extra dips and ridges because sigmoid is itself curvy. Gradient descent can get trapped in a fake "bottom" that isn't the real best answer.

Log loss: J(β) = −(1/n) Σ [ y·log(p) + (1−y)·log(1−p) ]
The formula Hour 2 will adopt instead of MSE. Full derivation and a worked example are two slides away — for now, just watch what it does to the SHAPE of the surface below.

How the curve below actually gets drawn, one β₁ at a time:

1

Pick a candidate β₁

Hold β₀ fixed at −4. Try one specific value for β₁, say −0.5.

2

Compute every applicant's p

For all 20 applicants: z = β₀+β₁x, then p = σ(z) — 20 predicted probabilities.

3

Score each one, then average

Run each (p, actual y) pair through the cost formula (MSE or log loss), average all 20 → ONE height on the surface.

4

Nudge β₁, repeat

Try −0.4, then −0.3, then −0.2... Each value produces one more height. Plot height vs. β₁ and the curve appears.

5

Why the shapes differ

MSE squares an already-curvy sigmoid output, and that extra curviness leaks straight into the surface as bumps. Log loss's logarithm exactly cancels sigmoid's curviness in the math — leaving one smooth bowl, guaranteed, for ANY dataset.

⚠️ MSE + sigmoid (non-convex): notice the bumps — multiple valleys, and gradient descent could easily stop in the wrong one.

Cost plotted against β₁ (β₀ held fixed) for our 20 applicants' data — this is the actual terrain gradient descent has to walk.

🎓 Optional · Going Deeper
Hour 2 · The Actual Guarantee Behind "One Smooth Bowl"

Why is log loss guaranteed convex?

The last slide claimed the log "exactly cancels" sigmoid's curviness. Here's the real derivation — not required going forward, but this is the actual math behind "one smooth bowl, always," for any dataset, any features.

1

You don't need σ(z) itself to be convex

z = β₀+β₁x is affine (linear) in β. Precomposing ANY convex function with an affine map stays convex — so sigmoid's own S-shape (convex then concave, bending twice) is irrelevant. The only question that matters: is −log(p(z)) convex in z, as a single variable?

2

Rewrite −log(p) algebraically

p = 1/(1+e^−z), so −log(p) = log(1+e^−z) — the "softplus" function. The log's whole job here is to cancel the exponential sitting inside sigmoid, turning a ratio into a clean sum.

3

Differentiate once

f(z) = log(1+e^−z)  →  f'(z) = σ(z) − 1  (chain rule, using sigmoid's own derivative identity)

4

Differentiate again

f''(z) = σ(z)(1−σ(z)) = p(1−p) — the exact same sigmoid-derivative fact that built Hour 2's gradient in the last hour, showing up again here.

5

p(1−p) is never negative

p always sits strictly between 0 and 1, so p(1−p) > 0 everywhere — peaking at 0.25 when p=0.5, shrinking toward 0 only as z→±∞. Second derivative never negative, anywhere → convex, guaranteed. (The mirror case, y=0, gives −log(1−p)=log(1+eᶻ) — same proof.)

6

Why MSE doesn't get this for free

(p−y)² is bounded between 0 and 1. A cost that's bounded but still rising as z moves toward "wrong" HAS to flatten out eventually — it can't climb past 1. That flattening is a reversal of curvature, and that reversal is exactly where the last slide's bumps came from. Log loss's cost is unbounded — it climbs to infinity, never plateaus, never bends back.

🎓 Optional takeaway: convexity in β never required sigmoid to be convex — only −log(p(z)) needed to be convex in z, and its second derivative p(1−p) is provably never negative. That single fact is the whole guarantee.
f''(z) = p(1−p) — the cost's own curvature
Hour 2 · Designing a Better Cost, From Intuition

What SHOULD a good cost punish?

Think about what "badly wrong" should mean for one applicant. If the loan actually got approved (y=1), being confidently wrong (p near 0) should hurt A LOT. Being confidently right (p near 1) should cost almost nothing. Two matching rules, one per true label:

✅

If y = 1: cost = −log(p)

p→1 (confident & correct) → cost→0. p→0 (confident & WRONG) → cost→∞. Exactly the punishment we wanted.

❌

If y = 0: cost = −log(1−p)

The mirror image. p→0 (confident & correct) → cost→0. p→1 (confident & WRONG) → cost→∞.

Hour 2 · One Formula, Both Cases at Once

Cross-entropy (a.k.a. log loss)

J(β) = −(1/n) Σ [ y·log(p) + (1−y)·log(1−p) ]
A clever trick: since y is always exactly 0 or 1, one of the two terms always vanishes — leaving just the rule that applies. Average that penalty over all n applicants.

Hour 2 · The Calculus Simplifies Beautifully

The gradient looks... exactly familiar

Work through the derivative of log loss (the sigmoid's own derivative cancels perfectly against the log's) and you land on the SAME "mistake × x" shape as linear regression's gradient — just with p (a sigmoid output) standing in for a straight-line prediction.

1

Compute the mistake per applicant

error = p − y  (predicted probability minus actual 0/1 label)

2

Slope for β₀

∂J/∂β₀ = (1/n) Σ (p − y)

3

Slope for β₁ (and every other β)

∂J/∂βₖ = (1/n) Σ (p − y) × xₖ  — one extra term per feature, same as always.

4

Update every β together

new βₖ = old βₖ − (learning rate) × slope for βₖ

5

Repeat until the slopes flatten

The exact same five steps as every gradient descent loop this course has used — nothing new in the loop itself.

✨ This is why logistic regression is taught right after linear regression: different hypothesis, different cost, IDENTICAL training loop.

Hour 3 · Two Numbers That Can't Be Faked At Once

Precision and recall

🎯

Precision = TP / (TP + FP)

In one line: "When we say yes, how often are we actually right?" Of everyone I predicted APPROVE, how many actually deserved it? Our model: 10/(10+1) = 90.9%. High precision = few bad loans wrongly approved.

🕸️

Recall = TP / (TP + FN)

In one line: "Of everyone who deserved a yes, how many did we actually catch?" Of everyone who deserved approval, how many did I catch? Our model: 10/(10+1) = 90.9%. High recall = few good applicants wrongly rejected.

⚖️ They trade off against each other. The fraud detector from the last slide had precision "undefined" (never predicted fraud) and recall = 0% — a perfect illustration of how one number alone hides the real story.
Hour 3 · Combining Them Into One Number

F1 score: the harmonic mean

F1 = 2 × (precision × recall) / (precision + recall)
Our model: 2×(0.909×0.909)/(0.909+0.909) ≈ 0.909. Punishes a lopsided precision/recall pair more harshly than a plain average would. In one line: F1 refuses to let a great precision hide a terrible recall (or vice versa) — you need to be reasonably good at BOTH to score well.

Which one matters more depends entirely on what a mistake COSTS in the real world:

🏦

Fraud detection → prioritize RECALL

Missing a fraudulent application (FN) costs far more than a false alarm that gets manually reviewed (FP).

🏠

Good-customer approval → prioritize PRECISION

Wrongly approving a loan that later defaults (FP) is often costlier than asking a good applicant to reapply (FN).

Hour 3 · 0.5 Was Never a Law of Nature

Pick the threshold that fits the cost of being wrong

1

Lower the threshold → approve more applicants

Recall goes up, precision typically goes down. Use when rejecting good customers is expensive — for business growth, or when a missed good applicant is costly.

2

Raise the threshold → fewer risky approvals

Precision goes up, recall typically goes down. Use when a bad loan (default) is expensive — exactly the tension every real credit-risk team lives with.

3

0.5 is just the "no opinion" default

It's only correct when both kinds of mistakes cost the same — rarely true in practice.

Hour 4 · Step 3 — The Trap: Error, or Just Unusual?

A credit score of 910 is impossible.
A $48,000 loan on a $54,000 salary isn't.

Not every extreme number is a mistake — and not every mistake looks extreme. The skill is telling them apart, using a real constraint on the data, not just a gut feeling.

🚫

Row 6 — Credit Score = 910

Real credit scores top out at 850. This is a data-entry error, no exceptions. Convert to missing — don't guess a nearby valid number.

🚫

Row 9 — Age = −3

A negative age isn't unusual, it's impossible. Same fix: convert to missing.

✅

Row 7 — $48,000 loan, $54,000 salary, REJECTED

Unusual, but entirely possible — and it's genuine signal about risk, not noise. Keep it. Deleting "weird-looking but real" rows is how models end up blind to exactly the cases that matter most.

📏 Rule of thumb: check against a real-world VALID RANGE (Age 18–100, Credit Score 300–850) — not against "does this look normal to me."
