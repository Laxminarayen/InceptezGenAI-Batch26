Logistic Regression

A linear model wrapped in the sigmoid function, trained by maximizing the likelihood of the observed labels rather than minimizing squared error. The workhorse behind more real-world credit, fraud, and risk decisions than almost any other single algorithm — precisely because it's fast, well-understood, and every coefficient has a clean interpretation.

1.The Sigmoid Function

σ(z) = 1 / (1 + e⁻ᶻ) Domain: all real numbers. Range: strictly (0, 1) — never touches 0 or 1 exactly. σ(0) = 0.5. As z→+∞, σ(z)→1; as z→−∞, σ(z)→0. σ'(z) = σ(z)(1−σ(z)) — the derivative is expressible entirely in terms of the function's own output, a property that drives the clean gradient in Section 5.

z is the log-odds (logit) by construction: odds = p/(1−p), z = log(odds), and inverting that relationship (odds = eᶻ, then p = odds/(1+odds)) algebraically simplifies to exactly σ(z). This is why a coefficient βₖ has a clean reading — a one-unit increase in Xₖ changes the log-odds of the positive class by βₖ, holding everything else fixed.

2.The Hypothesis & Decision Boundary

hβ(x) = σ(β₀ + β₁x₁ + … + βₚxₚ) = P(y=1 | x) The model outputs a probability, not a label. A separate decision rule (commonly p ≥ 0.5) turns it into a hard prediction.

Since σ(z)=0.5 exactly at z=0, the p≥0.5 rule reduces to β₀+β₁x₁+…+βₚxₚ ≥ 0 — a linear inequality. The decision boundary itself is therefore always a straight line (2 features), a plane (3 features), or a hyperplane (more) — Logistic Regression can only ever separate classes with something linear, regardless of how the probabilities inside the sigmoid curve.

3.From Maximum Likelihood to Log Loss

Each label yᵢ is modeled as a Bernoulli trial with success probability pᵢ = σ(zᵢ). The likelihood of the entire dataset, assuming independent rows, is the product of each row's probability of its own observed outcome:

L(β) = Π pᵢ^yᵢ (1−pᵢ)^(1−yᵢ) Maximizing L(β) is equivalent to maximizing its logarithm (log is monotonic), and equivalent again to minimizing the negative log-likelihood — which, divided by n, is exactly the log loss / cross-entropy formula: J(β) = −(1/n)Σ[yᵢlog(pᵢ) + (1−yᵢ)log(1−pᵢ)]. Log loss isn't an arbitrary design choice — it's the maximum-likelihood objective for a Bernoulli-distributed target, the direct classification analogue of Linear Regression's squared error being the maximum-likelihood objective under Gaussian noise.

4.Why Log Loss Is Convex

z = Xβ is affine in β, and precomposing a convex function of z with an affine map stays convex — so the question reduces to: is −log(σ(z)) convex in z? Its second derivative works out to p(1−p) (using p=σ(z)), which is strictly positive everywhere p is strictly between 0 and 1 — i.e. everywhere. Second derivative never negative ⇒ convex, guaranteed, for any dataset, any features. This is precisely why swapping MSE for log loss was necessary in the first place (Section on training, classwork notes): MSE composed with sigmoid is not guaranteed convex, and can trap gradient descent in a local minimum that isn't the true best fit.

5.The Gradient

∂J/∂βₖ = (1/n) Σ (pᵢ − yᵢ) xᵢₖ The sigmoid's own derivative identity (Section 1) cancels perfectly against the logarithm's derivative in log loss, collapsing to the same "mistake × feature" shape as Linear Regression's gradient — with pᵢ (a sigmoid output) standing in for a raw linear prediction. Same update rule, same five-step gradient descent loop, different hypothesis and cost function.

6.Multiclass: One-vs-Rest & Softmax

StrategyHow it works
One-vs-Rest (OvR)Train K independent binary classifiers, one per class ("class k vs. everything else"). Predict the class whose classifier outputs the highest probability. Simple, but the K probabilities aren't guaranteed to sum to 1.
Softmax (Multinomial)Generalizes the sigmoid directly: P(y=k|x) = e^(z_k) / Σⱼe^(z_j) — one linear score z per class, exponentiated and normalized so all K probabilities sum to exactly 1 by construction. The standard approach in modern libraries and the output layer of virtually every neural network classifier.

KNN and Decision Trees need no equivalent machinery at all — multiclass falls out of "count more labels" for free (see their references). This genuinely new machinery is specific to linear models like Logistic Regression.

7.Regularization

Exactly like Ridge/Lasso for Linear Regression (Polynomial Regression reference, Section 5), a penalty term can be added to log loss to shrink coefficients and reduce overfitting — especially relevant with many features or with polynomial/interaction terms added to a logistic model. scikit-learn's LogisticRegression applies L2 regularization by default (parameterized as C, the inverse of regularization strength — smaller C means stronger regularization, the opposite direction from Ridge's α).

8.Evaluation Beyond Accuracy

Accuracy, precision, recall, and F1 (classwork notes) all depend on a chosen decision threshold. Two threshold-independent tools evaluate the underlying probabilities directly:

  • ROC curve — plots True Positive Rate against False Positive Rate as the threshold sweeps from 0 to 1. AUC (Area Under the Curve) summarizes it in one number: 0.5 = no better than random guessing, 1.0 = perfect separation.
  • Precision-Recall curve — plots precision against recall across the same threshold sweep; more informative than ROC-AUC when the positive class is rare (imbalanced data), because it doesn't dilute performance with the (usually large) number of true negatives the way ROC/AUC can.

10.Worked Example

from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report, roc_auc_score
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

model = make_pipeline(
    StandardScaler(),
    LogisticRegression(C=1.0, class_weight="balanced", max_iter=200),
)
model.fit(X_train, y_train)

y_pred = model.predict(X_test)
y_proba = model.predict_proba(X_test)[:, 1]

print(classification_report(y_test, y_pred))
print("ROC-AUC:", roc_auc_score(y_test, y_proba))

11.Summary

The whole idea, in one paragraph

Logistic Regression squashes a linear score through the sigmoid to produce a valid probability, then trains by maximizing the likelihood of the observed 0/1 labels — an objective that simplifies to log loss, provably convex, and whose gradient collapses to the same "mistake × feature" shape used everywhere else in this course. Its decision boundary is always linear, its coefficients are individually interpretable as log-odds effects, and Softmax extends the exact same idea to any number of classes at once. Threshold-independent tools like ROC-AUC and the Precision-Recall curve evaluate the underlying probabilities directly, which is often more honest than any single accuracy number at one fixed threshold.
