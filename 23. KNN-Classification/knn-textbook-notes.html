K-Nearest Neighbors (KNN)

A lazy learner: no coefficients, no cost function, no training phase in the usual sense. Every prediction is answered fresh, by finding the K most similar stored examples and asking what happened to them.

1.Lazy Learning, Defined

Every other model in this course is eager: it compresses the training data into a fixed set of parameters (β's, a tree structure) before ever seeing a new point, then discards the training data. KNN is lazy (instance-based): "training" is just storing the data verbatim — no compression, no optimization, no convergence. All the computation happens at prediction time.

2.Distance Metrics

Minkowski distance: d(A,B) = ( Σ|Aᵢ−Bᵢ|^q )^(1/q) The general form. q=2 gives Euclidean distance (straight-line, "as the crow flies"). q=1 gives Manhattan distance (city-block, sum of absolute differences — less sensitive to any single large deviation than Euclidean). Categorical features commonly use Hamming distance instead: the count of positions where two vectors disagree.

The choice of metric rarely matters as much as scaling correctly (Section 3) — but it is a design decision, not a law of nature, and worth stating explicitly when reporting results.

3.Why Scaling Is Mandatory

Distance is a sum of squared (or absolute) differences across all features, unweighted by default. A feature spanning 18–70 contributes a term dozens of times larger than a feature spanning 1–10, for a difference of equal "importance" in either — the larger-range feature silently dominates every distance calculation. Standardizing every feature (z-score: subtract the mean, divide by the standard deviation) puts them on equal footing before distance is ever computed. Unlike Gradient Descent (where unscaled features only slow convergence), unscaled features in KNN produce actively wrong neighbor sets and therefore wrong predictions — there is no "it still converges eventually" fallback.

4.The Algorithm

  1. Store the full training set (features + labels).
  2. For a new point x: compute distance from x to every stored training point.
  3. Sort all training points by that distance, ascending.
  4. Take the K closest.
  5. Aggregate — majority vote of their labels (classification) or mean of their targets (regression, see the KNN Regression reference).

5.Choosing K

K controls the same bias-variance tradeoff as polynomial degree or tree depth:

  • Small K (e.g. K=1) — low bias, high variance. The decision boundary chases every individual point, including noise and outliers.
  • Large K — high bias, low variance. Predictions smooth toward the global majority class, losing local structure.

Chosen the same honest way as everywhere else: split into train/test (or k-fold cross-validation), sweep K across a reasonable range, and pick the value that minimizes held-out error — never training error, since K=1 always achieves zero training error trivially (a point's nearest neighbor is itself).

For binary classification, prefer odd K to avoid tied votes. If a tie still occurs (multiclass, or an even K), common tie-breaks are: fall back to the single nearest neighbor, or use distance-weighted voting (Section 6).

6.Distance-Weighted Voting

weight(neighbor) = 1 / distance(x, neighbor) Instead of every one of the K neighbors casting an equal vote, closer neighbors count for more. Softens the impact of the K-th (farthest, least relevant) neighbor without needing to shrink K itself. In scikit-learn: weights='distance' instead of the default 'uniform'.

7.The Curse of Dimensionality

As the number of features grows, the volume of the feature space grows exponentially, but the number of training points stays fixed — so points become sparse, and every point's distance to every other point starts to converge toward roughly the same value. "Nearest" stops carrying much information: in very high dimensions, a query point's nearest neighbor and farthest neighbor can be almost equally far away. This is the formal reason KNN is typically applied to a modest, carefully-chosen or dimensionality-reduced feature set rather than hundreds of raw columns — a constraint parametric models like Logistic Regression face far less severely.

8.Computational Cost & Speedups

TrainingPrediction (one query)
Brute-force KNNO(1) — just store the dataO(n·p) — compare to every point, across p features
KD-Tree / Ball TreeO(n log n) — build a spatial index onceO(log n) typical — prune large regions of the space, in low-to-moderate dimensions

KD-Trees and Ball Trees lose their advantage in very high dimensions (the curse of dimensionality again — pruning stops being effective), at which point approximate nearest-neighbor libraries (e.g. FAISS, Annoy) trade a small amount of accuracy for large speed gains at production scale.

11.Worked Example

from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import GridSearchCV

pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())
param_grid = {"kneighborsclassifier__n_neighbors": range(1, 21, 2)}

grid = GridSearchCV(pipe, param_grid, cv=5, scoring="f1")
grid.fit(X_train, y_train)

print("Best K:", grid.best_params_)
print("Test accuracy:", grid.score(X_test, y_test))

12.Summary

The whole idea, in one paragraph

KNN fits nothing — it stores the training set and, at prediction time, finds the K nearest points by some distance metric and votes (or averages). Feature scaling isn't a nicety here, it's a correctness requirement, because distance is the entire algorithm. K trades variance for bias exactly like every other complexity knob in this course, and is chosen the same honest way: held-out performance, not training performance. Its Achilles' heel is high dimensionality, where "nearest" quietly stops meaning anything — the reason KNN pairs best with a small, deliberate feature set rather than everything you have.
