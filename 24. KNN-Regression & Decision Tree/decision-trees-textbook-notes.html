Decision Trees — Entropy & Information Gain

A recursive, greedy partitioning algorithm: repeatedly ask the single best yes/no question about the data, split on it, and recurse on each resulting group until every leaf is pure (or a stopping rule triggers). No distance, no coefficients — just a sequence of questions, each one chosen to remove as much uncertainty as possible. Also: KNN Regression, the one-word extension of KNN to numeric targets.

0.KNN Regression, Briefly

One change from KNN Classification: replace the majority vote over the K nearest neighbors' labels with the mean of their numeric targets.

ŷ(x) = (1/K) Σ yᵢ, for the K nearest neighbors of x Same distance metric, same mandatory scaling, same bias-variance role for K (small K chases noise into a jagged step function; large K oversmooths toward the global mean) — see the KNN reference for the full treatment. Distance-weighted averaging (weight ∝ 1/distance) is the regression analogue of Section 6 in that reference.

1.The Tree as a Recursive Partition

A Decision Tree is, structurally, nothing more than nested if/else statements. The only hard question the algorithm has to answer, at every single node: which feature, split which way, produces the two "purest" possible child groups? Answering that question requires a way to measure "purity" numerically.

2.Entropy

H(S) = −Σ pᵢ log₂(pᵢ) Borrowed directly from Shannon's information theory, where H(S) is interpreted as the expected number of bits needed to communicate a randomly drawn label from S. H(S)=0 when S is pure (one label, pᵢ=1, zero bits of surprise needed). H(S) is maximized (log₂(number of classes)) when labels are as evenly mixed as possible — for two classes, that maximum is exactly 1.0 at a 50/50 split.

3.Information Gain

IG(S, feature) = H(S) − Σ (|Sᵥ|/|S|) · H(Sᵥ) H(S) is the parent node's entropy before splitting. The sum is the weighted average entropy of the child groups Sᵥ produced by splitting on that feature (weighted by what fraction of the data lands in each child). Information Gain is how much entropy the split removes — the tree, at every node, picks whichever available feature maximizes this quantity.

Dividing Information Gain by the parent's own entropy expresses it as a percentage of that node's uncertainty resolved — useful for communicating "this one question explained 72% of the confusion in this group" in plain language to a non-technical audience.

4.The Greedy, Recursive Algorithm (ID3-style)

  1. Compute entropy of the current node's data.
  2. For every remaining (unused) feature, compute Information Gain if the data were split on it.
  3. Split on the feature with the highest Information Gain — that feature becomes this node's question.
  4. For each resulting child: if it's pure (entropy 0) or no features remain, make it a leaf, labeled with the majority class of the rows that reached it. Otherwise, recurse — treat the child as a new "current node" and repeat from step 1, using only the rows and features not yet consumed.

This specific recipe (entropy + Information Gain) is the ID3 algorithm, historically the first widely-used Decision Tree induction method. Modern implementations (including scikit-learn's DecisionTreeClassifier) generalize this into CART (Classification and Regression Trees), which supports both entropy and Gini impurity (Part 2, Section on Gini) and produces strictly binary splits even for multi-category features.

5.Why Greedy, Not Optimal

At each step, the tree picks the single best immediate split — it never looks ahead to check whether a locally worse split might enable a globally better tree two levels down. Finding the provably optimal tree over all possible split sequences is NP-hard for any non-trivial dataset, so every practical Decision Tree algorithm, including scikit-learn's, is greedy by necessity. In practice this rarely matters much — the trees produced are excellent, just not mathematically guaranteed to be the single best possible tree.

6.The R² Parallel

Linear RegressionDecision Tree
SST — spread around the mean, before fittingH(root) — entropy of the target before any split
SSR — spread the fitted line explainsInformation Gain — confusion the split removes
SSE — spread left unexplainedWeighted entropy of the children — confusion remaining
R² = SSR/SSTIG / H(root) = fraction of uncertainty resolved

Both start from a baseline "spread" (variance around the mean, for numbers; the overall class mix, for categories) and measure what fraction one predictor accounts for. Same underlying logic, different units.

7.Summary

The whole idea, in one paragraph

A Decision Tree greedily and recursively asks "which available feature, split which way, removes the most entropy?" — computed the same way, at every node, until every leaf is pure or a stopping rule triggers. It's the ID3 recipe, generalized by modern libraries into CART. Categorical features split cleanly on their existing categories; numeric features and the Gini alternative to entropy are exactly where Part 2 of this reference picks up.
