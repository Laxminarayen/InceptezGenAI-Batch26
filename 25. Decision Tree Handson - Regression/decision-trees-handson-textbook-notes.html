1.Numeric Feature Splits

A categorical column arrives pre-grouped ("Property_Area = Urban?"). A numeric column has no such ready-made groups — the tree has to search for the best threshold itself.

  1. Sort all n values of the feature.
  2. Consider the midpoint between every pair of adjacent sorted values as a candidate threshold — n sorted values yield n−1 candidates.
  3. For each candidate, split into "< threshold" / "≥ threshold" and compute Information Gain (or Gini Gain) exactly as for a categorical split.
  4. Keep the threshold with the highest gain.

The entropy/Gini math never changes — only one extra search step (over candidate thresholds) gets bolted on. A numeric column then competes on completely equal footing with categorical columns for the title of "best split at this node."

2.The Gini Index

Gini(S) = 1 − Σ pᵢ² A pure group gives Gini=0. A K-way even split gives Gini = 1 − K·(1/K)² = 1 − 1/K — for two classes, a maximum of 0.5 (vs. entropy's maximum of 1.0 for two classes). No logarithm required — just squaring and subtracting, meaningfully cheaper to compute across millions of rows and splits.

Entropy and Gini virtually always rank candidate splits identically — different absolute numbers, same decisions. This is why scikit-learn's DecisionTreeClassifier defaults to criterion='gini': cheaper, and the tree it produces is essentially the same one entropy would have produced.

3.Regression Trees

Swap the impurity measure from entropy/Gini (defined for categorical labels) to variance (defined for numeric targets), and the identical recursive algorithm predicts numbers instead of classes.

Variance(S) = (1/|S|) Σ (yᵢ − ȳ)² A split is scored by how much it reduces the weighted average variance of the children versus the parent — the direct numeric analogue of Information Gain. Each leaf's prediction is simply the mean of the target values that landed there.

Because every leaf outputs one constant value, a regression tree's prediction surface is always a step function (a staircase in 1D) — never a smooth curve, no matter how deep the tree grows. More depth means more, narrower steps; it can approximate a smooth function arbitrarily closely, but will never actually produce a smooth line the way Linear or Polynomial Regression does.

4.Overfitting & Pruning

An unrestricted tree can keep splitting until every leaf contains a single training row — perfect training accuracy, and badly overfit. Two families of control:

  • Pre-pruning (early stopping) — stop growing based on a rule checked during construction: max_depth, min_samples_split (minimum rows required to consider splitting a node), min_samples_leaf (minimum rows required to keep a leaf), max_leaf_nodes.
  • Post-pruning (cost-complexity pruning) — grow the full tree first, then remove branches whose contribution to reducing impurity doesn't justify their added complexity, controlled by a single parameter ccp_alpha (larger α prunes more aggressively). Chosen via cross-validation, the same honest way as every other complexity hyperparameter in this course.

5.Feature Importance

Summing the (weighted) impurity decrease every time a feature is used for a split, across the whole tree, gives a natural importance ranking — scikit-learn exposes this as .feature_importances_. The same caveat that applies to Random Forest's Mean Decrease in Impurity applies here even more strongly for a single tree: features with many distinct values get more chances to be picked as a split purely from having more candidate thresholds, which can bias raw importance scores independent of true predictive value.

6.One Tree vs. a Forest

Everything in this reference describes a single tree — and a single tree's biggest weakness is exactly what motivates the next major topic in this course: change a handful of training rows and the entire structure, from the root down, can come out completely different (see the worked example in the Random Forest reference, Section 1). Random Forest is literally many of these trees, each grown on a bootstrapped, feature-randomized resample of the data — everything here (entropy/Gini, recursive splitting, regression via variance) still applies to every individual tree inside the forest.

8.Worked Example

from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import GridSearchCV

param_grid = {
    "max_depth": [2, 3, 4, 5, None],
    "min_samples_leaf": [1, 5, 10],
    "criterion": ["gini", "entropy"],
}
grid = GridSearchCV(DecisionTreeClassifier(random_state=42), param_grid, cv=5, scoring="f1")
grid.fit(X_train, y_train)

print("Best params:", grid.best_params_)

9.Summary

The whole idea, in one paragraph

A numeric column earns its place in a tree by searching over candidate thresholds, then competing on the same entropy/Information-Gain (or Gini) footing as every categorical column. Gini is entropy's cheaper, near-equivalent cousin and scikit-learn's default. Swap the impurity measure to variance and the identical recursion predicts numbers via a step-function surface instead of classes. Left unchecked, a tree overfits by construction — pre-pruning (depth/leaf-size limits) and post-pruning (cost-complexity, ccp_alpha) are the two standard controls, both chosen by cross-validation. And a single tree's core weakness — instability from small data changes — is precisely the problem Random Forest exists to solve.
