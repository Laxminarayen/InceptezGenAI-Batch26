Numeric Splits → The Gini Index

Entropy needs a logarithm.
Is there a cheaper way to measure "mixed up"?

Yes — and it's the DEFAULT setting in almost every tree-building library you'll ever use.

Gini · A Different Ruler, Same Thing Being Measured

Gini asks the same question, skips the logarithm

Remember the candy-bag intuition from last class — 0 means "totally sorted," highest means "a 50/50 mix"? The Gini Index measures that exact same feeling, with plain multiplication instead of logarithms.

Gini(S) = 1 − Σ pᵢ²
Square each label's fraction, add the squares up, subtract from 1. A pure group (p=1) gives Gini = 1 − 1² = 0. A 50/50 group gives Gini = 1 − (0.5²+0.5²) = 0.5 — its own "maximum confusion," just on a different scale than entropy's 1.0.
🧮 No log₂ anywhere — just squaring and subtracting. That's the entire practical difference. Cheaper for a computer, especially across millions of rows.

Regression Trees · One Small Change, Again

Same tree, same recursion, new scoreboard

Remember Hour 1's one-word change to KNN — vote became average? The identical thing happens to Decision Trees. Instead of "which question un-mixes the CLASSES the most?", ask "which question makes the NUMBERS inside each group most similar to each other?"

❓

Classification tree

Splits to reduce ENTROPY or GINI. Every leaf votes a category.

📈

Regression tree

Splits to reduce VARIANCE. Every leaf predicts the MEAN of whoever lands there.

Regression Trees · Depth Is This Tree's "K"

Sweep depth the same honest way

1

Depth 1: barely asks anything

One split for the whole dataset — high error on train AND test. Underfit.

2

Depth ≈ 2: the sweet spot

Test error bottoms out — enough questions to track the real trend, not enough to chase noise.

3

Deep trees: memorize, don't generalize

Training error → 0 as depth grows, while test error climbs back up. Classic overfitting.
