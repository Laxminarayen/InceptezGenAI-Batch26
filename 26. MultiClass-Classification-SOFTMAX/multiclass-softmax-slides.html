Revision · The First Fork In The Road

Regression or classification — it starts with Y

📈

Regression

Target Y is continuous — any floating-point value. Linear, Polynomial Regression: input X's, output a number.

🏷️

Classification

Target Y is discrete — a category from a fixed set: 0/1, or Low/Medium/High. That's where we live today.

👀 Same X's, same columns — the only thing that changes the whole family of models is what kind of Y you're trying to predict.
Revision · Parametric vs. Non-Parametric

Models with dials, and models with none

🎛️

Parametric — Linear & Logistic Regression

Learn a fixed set of knobs — β₀, β₁ ... βₙ — from training data. Once learned, the training data itself can be thrown away; only the parameters matter at prediction time.

🧭

Non-parametric — KNN & Decision Trees

No learnable dials. KNN makes no assumption about the relationship at all — it just measures distance to every stored point. Decision Trees ask a sequence of yes/no questions instead.

Pipeline either way: Data → Pre-process/EDA (missing values, outliers, inconsistent text, encoding, scaling, feature selection) → Model Train → Predict.

From 2 Classes to K · KNN

KNN handles this for free

1

Nothing about "distance" changed

Still Euclidean (or Manhattan/Cosine) distance from a new applicant to every stored training point — the formula never knew about class labels in the first place.

2

Only the vote changes

Binary KNN took a majority vote between 2 labels. Multiclass KNN takes the mode — whichever of Low/Medium/High appears most often among the K nearest neighbors.

3

K = 3 example

A new applicant's 3 nearest neighbors are labeled Medium, Medium, High → mode = Medium. Same rule works for any number of classes.

✅ Lazy learner, no training step, no dials — and completely indifferent to how many classes Y has.
From 2 Classes to K · Decision Trees

Entropy already generalizes

The impurity formula was never written just for 2 classes: H(S) = −Σ p(xᵢ)·log₂ p(xᵢ), summed over however many classes are actually present in that node.

12 samples, 3 classes, evenly split
p(Low) = p(Medium) = p(High) = 4/12 = 1/3 each.
H(S) = −3 × (1/3 · log₂(1/3)) = 1.585

From 2 Classes to K · The Ceiling Moves

Max entropy is now log₂(K)

With 2 balanced classes the worst-case impurity was 1.0 bit. Add a third evenly-split class and the ceiling itself rises — more classes means more ways to be uncertain. Try it:

K classes
3
max H(S) = log₂(K)
1.585
A node can never be MORE confused than a perfectly even split across all K classes — that's exactly what log₂(K) measures.
From 2 Classes to K · Logistic Regression's Turn

Sigmoid only ever gives one number

σ(z) outputs a single probability between 0 and 1 — perfect for "is it class 1?", meaningless for "which of three classes is it?". Unlike KNN and Decision Trees, logistic regression cannot just be reused as-is.

⚠️ One line, one probability. Three classes need at least three numbers that make sense together — logistic regression itself has to be reworked.
From 2 Classes to K · First Instinct

One-vs-Rest: 3 classes, 3 models

Train one binary logistic regression per class, each one asking "is it THIS class, or anything else?" With K classes, that's K independent models (or K output nodes).

A

Medium and High both get folded into "Rest."

B

Model B — Medium vs. Rest

Low and High both get folded into "Rest."

C

Model C — High vs. Rest

Low and Medium both get folded into "Rest."

🚧 Each model is trained in isolation — their 3 output scores have no reason to add up to 1, and they can disagree with each other. Workable, but not elegant.
From 2 Classes to K → Softmax

What if logistic regression
was properly rebuilt for K classes?

One coherent model, K outputs that always add up to exactly 1.0 — no separate models, no disagreement. That's Softmax Regression.

Softmax Regression · The Setup

One-hot encode the target first

Each class becomes its own column of 0's and 1's — a "1" in exactly one position, marking which class that row belongs to.

Softmax Regression · K Regression Lines

Every class gets its own line

Instead of 1 equation, fit K of them — one z per class, all sharing the same input x, each with its own intercept and slope.

zₖ = β₀,ₖ + β₁,ₖ · x
3 classes → 3 independent (β₀, β₁) pairs, trained together as one model.

Softmax Regression · By Hand, Once

One applicant, credit index x = 3.31

1

z₀ (Low) = 4.50 + (−1.20 × 3.31)

= 4.50 − 3.972 = 0.528

2

z₁ (Medium) = 0.80 + (0.25 × 3.31)

= 0.80 + 0.828 = 1.628

3

z₂ (High) = −3.20 + (1.10 × 3.31)

= −3.20 + 3.641 = 0.441

Three raw scores — not probabilities yet. Medium is already the largest, but by how much? That's what softmax answers next.
Softmax Regression · Scores → Probabilities

The softmax formula

p̂ₖ = e^zₖ / (e^z₀ + e^z₁ + e^z₂)
Exponentiate every score (always positive, and the biggest score gets stretched out the most), then divide by the total — so all K probabilities land between 0 and 1 and add up to exactly 1.
Why exponentiate instead of just dividing the raw scores by their sum? Negative scores would break a plain average — e^z fixes that, and rewards the winner more than a linear average would.

Softmax Regression · Reading The Result

Predict = argmax of the softmax output

[0.20, 0.61, 0.18] → the largest entry wins → this applicant is classified Medium Risk, with the model's own confidence built right in. One model, one coherent probability distribution — the exact upgrade One-vs-Rest couldn't give us.

Confusion Matrix · 2×2 Grows Up

Now it's a K × K grid

Binary classification had 4 cells: TP, TN, FP, FN. With 3 classes, every one of the 3 actual classes can be predicted as any of the 3 classes — 9 cells, and the diagonal is still "got it right."

Rows = actual class. Columns = predicted class. Every off-diagonal cell is a specific, nameable kind of mistake — e.g. "actually High, predicted Medium."
Confusion Matrix · A Worked 3×3 Example

Where does the model actually get confused?

30 held-out applicants. The diagonal (green) is correct; everything else is a specific misclassification worth naming out loud.

Here: High risk applicants are never mistaken for Low — but Medium and High get confused with each other 3 times combined. That pattern matters more than the overall accuracy number.

Confusion Matrix · From Matrix to Metrics

Precision & recall, one class at a time

1

Pick one class, treat it as "the positive"

Same One-vs-Rest idea as before — but now for grading a model, not training one.

2

Precision(High) = TP(High) / all predicted High

Of everyone the model called High risk, what fraction actually were?

3

Recall(High) = TP(High) / all actually High

Of everyone who really was High risk, what fraction did the model catch?

Do this for Low, Medium, and High separately — three precision numbers, three recall numbers, then F1 per class if you want one summary number each.
