The ML/DL workflow, every time: Data → Preprocessing (what is the current shape of this data?) → Choice of model (tree-based? linear? distance-based?) → Config / hyperparameter tuning → Performance — how do we actually measure it? That last question is today's session.

Confusion Matrix — Binary, Recap

Predicted ApprovePredicted Reject
Actual ApproveTrue ApprovedFalse Rejected
Actual RejectFalse ApprovedTrue Rejected
Accuracy = (True Approved + True Rejected) / Total
  • Precision — when I predict Approved, how often is it actually Approved? = True Approved / (True Approved + False Approved)
  • Recall — out of actual approvals, how many did the model actually find? = True Approved / (True Approved + False Rejected)

Confusion Matrix — Multiclass (Low / Medium / High)

Accuracy = Sum of the diagonal / Total
ClassPrecisionRecall
LowTrue Low / (True Low + confused-as-Low)True Low / (all actual Low)
MediumTrue Med / (True Med + confused-as-Med)True Med / (all actual Medium)
HighTrue High / (True High + confused-as-High)True High / (all actual High)

Watch out: a model can look good simply by predicting the majority class well — while barely recalling anything from the smaller classes. That's the accuracy paradox, and it's exactly what imbalanced classes cause.

Imbalanced Classes

Plot how often each class of Y occurs and you often get a fat "head" (majority class) and a long "tail" (minority classes) — e.g. Class A = 80%, Class B = 15%, Class C = 5%.

A worked fraud example

Predicted Non-FraudPredicted FraudTotal
Actual Non-Fraud (0)450 ✓50 ✗500
Actual Fraud (1)45 ✗5 ✓50
Accuracy = (450 + 5) / 550 = 455/550 ≈ 83%

83% accuracy — while catching only 5 of the 50 actual frauds. The real question: can the data itself be engineered so the model actually learns the rare, fraudulent cases?

Two levers

  • Undersampling — shrink the majority class down toward the minority's size (e.g. 455 non-fraud → 55, matching the 55 fraud rows). Simple, but may reduce your model's understanding of the majority class and throws away information.
  • Oversampling — grow the minority class up instead, increasing its count toward the majority's size.

Smarter oversampling — SMOTE & ADASYN

  • Random Oversampling — literally duplicate minority rows. Risks overfitting to the same few examples.
  • SMOTE (Synthetic Minority Oversampling Technique) — find each minority point's nearest minority neighbors (KNN), and generate brand-new synthetic points along the line between them, with a little noise added — new data, not copies.
  • ADASYN (Adaptive Synthetic Sampling) — same idea as SMOTE, but generates more synthetic points near the minority examples that are hardest to learn (outliers, near the decision boundary).

You don't always need a perfect 50/50 split — 55/45, 60/40, even 70/30 can be the right target, depending on the actual cost of each kind of mistake for that business.

How Do We Handle Imbalance Via Model Performance Quantification?

  1. Accuracy fails — it favors class skewness.
  2. Precision & Recall — and combining the two into F1 Score.

There's more than one way to average two numbers: (1) Arithmetic Mean, (2) Exponential Moving Average, (3) Weighted Moving Average, (4) Harmonic Mean — dividing the total number of values by the sum of their reciprocals. F1 uses the harmonic mean.

Why harmonic mean — the driving analogy

Drive 60 km out at 60 km/h, then the same 60 km back at 20 km/h.

  • Arithmetic mean: (60 + 20) / 2 = 40 km/h — wrong. It ignores that far more time was spent at the slower speed.
  • The truth: 1 hour out (60÷60) + 3 hours back (60÷20) = 120 km in 4 hours = 30 km/h.
H = 2ab / (a + b)  →  2 × 60 × 20 / (60 + 20) = 30 km/h The harmonic mean represents the "true rate" of a system — exactly what's needed when combining Precision and Recall.
F1 Score = 2 · Precision · Recall / (Precision + Recall) The harmonic mean of Precision and Recall. It drops fast the moment either one is weak — unlike a plain average, which can stay misleadingly high.
