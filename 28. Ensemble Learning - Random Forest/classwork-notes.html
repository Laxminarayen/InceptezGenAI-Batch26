Before Anything Else: Models Go Stale

10 rows trained the model. Row 11 just showed up with new information. The instinct to resist is: "my model already saw very good data — do I still need to retrain?" Yes — good data once isn't all the data forever. New information changes what the model should have learned. Retraining isn't a failure of the first model, it's routine maintenance.

Decision Trees — the Disadvantage

Everything today starts from one uncomfortable fact about a single Decision Tree:

  • Extremely sensitive to training data — change a handful of rows, and the root split, entropy calculations, and every downstream decision can come out completely different.
  • The whole structure can flip — Root Node → Entropy → Information Gain is a chain reaction. Perturb the input even slightly and the tree that comes out the other end can look nothing like the last one.
  • One perspective on the data — a single tree only ever tells you the one story shaped by exactly the rows and columns it happened to train on.

Ensemble Learning, Defined

Five spam filters vote on the same email: Spam, Spam, Not Spam, Spam, Spam. Four out of five say Spam — the ensemble's answer is Spam. That's the whole idea: combine many moderately good models to produce one better output.

Main Objective: Better Accuracy + Better Generalization Not overfitting — achieved by combining multiple Decision Trees, each seeing the data from a slightly different perspective.

The four main ensemble techniques

  1. Bagging — today's entire focus. Bootstrap + Aggregate; the engine behind Random Forest.
  2. Boosting — each new model focuses on fixing the previous one's mistakes. Weekend reading.
  3. Stacking — train a "meta-model" on top of other models' predictions. Weekend reading.
  4. Voting — combine different model types directly by majority vote or averaging. Weekend reading.

Random Forest = Bagging + Randomness

Multiple trees → forest. Random Forest is Bagging applied to Decision Trees, with extra randomness injected while building each tree — in both the rows and the columns it's allowed to see. It's a fairly new field, and the "Random" in the name refers to exactly two design choices.

Step 1 — Bootstrapping: random rows, with replacement

To build Tree 1's dataset, sample rows randomly with replacement from R1–R5. The same row can be picked more than once, and some rows won't get picked at all.

Boot 1 = [ R1, R1, R3, R2, R4 ] R1 was picked twice, R5 wasn't picked at all. The rows left out of a tree's bootstrap sample are that tree's Out-of-Bag (OOB) rows.

Step 2 — Random Features: random columns, per split

Each tree isn't allowed to look at every column when deciding a split — only a random subset. That's the second "Random" in Random Forest's name. Rule of thumb for how many columns to keep: roughly √(total columns) — e.g. with 9 columns, about 3 are considered at each split.

If Tree 1 is forced to split on {Age, Gender} instead of Credit Score, it has to find a different — but still valid — way to separate the data. That's exactly how T1 ≠ T2 ≠ T3, even though every tree runs the same underlying Decision Tree algorithm.

Random Forest = Random Rows + Random Columns + Trees The balance is deliberate: enough "tree stretch" that each tree is genuinely different, but not so much randomness that any single tree becomes useless on its own.

Bagging, in full: Bootstrapping + Aggregation

  1. Step 1 — Bootstrap N datasets: Boot Dataset 1, Boot Dataset 2, … Boot Dataset N — each a random-with-replacement, random-columns sample.
  2. Train N independent trees: each bootstrapped dataset trains its own standalone Decision Tree (same algorithm — Entropy → Information Gain → Root Node). Tree 1, Tree 2, … Tree N.
  3. Step 2 — Aggregate the outputs: for classification, every tree votes and the mode (majority label) wins; for regression, take the average of every tree's prediction.

Out-of-Bag (OOB) Evaluation

Because bootstrapping samples with replacement, each tree is never trained on every row — the leftovers are its OOB set.

TreeNever trained onUse those rows to…
Tree 1R5Test Tree 1 on R5
Tree 2R1, R3Test Tree 2 on R1 and R3

Out-of-Bag Evaluation emulates a validation/train split — using rows that are totally unseen by that specific tree, internally, without setting anything aside up front. The OOB Score scores every row using only the trees that never saw it during training, then averages across all rows: cross-validation, essentially for free. It's a big part of why Random Forests are notoriously hard to overfit badly — every tree is quietly being checked by the rows it never got to memorize.
