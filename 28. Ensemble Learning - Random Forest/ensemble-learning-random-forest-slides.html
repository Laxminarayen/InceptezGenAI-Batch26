Decision Trees · The Disadvantage

One tree, one very opinionated structure

1

Extremely sensitive to training data

Change a few rows, and the root split, the entropy calculations, the whole tree can come out looking completely different.

2

The whole structure can flip

Root Node → Entropy → Information Gain is a chain — perturb the input even slightly, and every downstream decision can change.

3

One perspective on the data

A single tree only ever tells you one story about the dataset — the one shaped by exactly the rows and columns it happened to be trained on.

Random Forest · The One-Line Definition

Bagging, plus a bit of randomness

Multiple Trees → Forest
Random Forest = Bagging applied to Decision Trees, with extra randomness injected while building each tree — in both the rows and the columns it's allowed to see.

It's a fairly new field as these things go — and the "Random" in the name refers to exactly two design choices, both coming up next.

Random Forest · Step 1

Bootstrapping — random rows, with replacement

To build Tree 1's dataset, sample rows randomly with replacement from R1–R5. The same row can be picked more than once — and some rows won't get picked at all.

Boot 1 = [ R1, R1, R3, R2, R4 ]
R1 was picked twice, R5 wasn't picked at all. The rows left out of a tree's bootstrap sample are that tree's Out-of-Bag (OOB) rows — more on that in Section 4.
Random Forest · Step 2

Random Features — random columns, per split

Each tree isn't allowed to look at every column when deciding a split — only a random subset of them. That's the second "Random" in Random Forest's name.

Example: 4 rows, 9 columns
√9 ≈ 3 columns per split
Common rule of thumb
√(total columns)
If Tree 1 is forced to split on {Age, Gender} instead of Credit Score, it must find a different — but still valid — way to separate the data. That's exactly how T1 ≠ T2 ≠ T3, even though every tree uses the same Decision Tree algorithm underneath.
Random Forest · Putting It Together

Random Forest =
Random Rows + Random Columns + Trees

The balance is deliberate: enough "tree stretch" that each tree is genuinely different, but not so much randomness that any single tree becomes useless on its own.

Bagging · The Full Picture

Bootstrapping + Aggregation

1

Step 1 — Bootstrap N datasets

Boot Dataset 1, Boot Dataset 2, … Boot Dataset N — each one a random-with-replacement, random-columns sample.

2

Train N independent trees

Each bootstrapped dataset trains its own standalone Decision Tree — same algorithm (Entropy → Information Gain → Root Node) as always. Tree 1, Tree 2, … Tree N.

3

Step 2 — Aggregate the outputs

For classification: every tree votes, take the mode (majority label). For regression: take the average of every tree's prediction.

✓ That's the whole algorithm: Bootstrap → many trees → Aggregate. Random Forest just adds the random-columns twist inside step 1.
Out-of-Bag (OOB) · A Validation Set You Already Have

Every tree leaves some rows unseen

Because bootstrapping samples with replacement, each tree is never trained on every row — the leftovers are its OOB set.

Out-of-Bag · Scoring the Whole Forest

The OOB Score — cross-validation, for free

Score every row using only the trees that never saw it during training, then average across all rows. No separate held-out validation set required — the randomness of bagging already built one in.

✓ This is why Random Forests are famously hard to overfit badly — every tree is quietly being checked by the rows it never got to memorize.
