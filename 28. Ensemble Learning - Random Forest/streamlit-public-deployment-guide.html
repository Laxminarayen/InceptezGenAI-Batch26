Streamlit Public Deployment

Your Random Forest app already runs on your own laptop (see the local Setup & Run guide). This guide takes the exact same folder and puts it on the public internet, with a real URL you can share with anyone — no server administration required. The whole path is: GitHub account → GitHub Desktop → push your files → Streamlit Community Cloud reads your repo and hosts it for you.

1.What You Need Before You Start

  • A free GitHub account (github.com) — this is where your code will live publicly.
  • A free Streamlit Community Cloud account (share.streamlit.io) — sign in with the same GitHub account, no separate password needed.
  • Your working StreamlitApp folder from class, containing at minimum: app.py, requirements.txt, and every .joblib/.json file app.py loads.
Why a separate deployment step at all? Running streamlit run app.py locally only serves the app to your own machine, on your own network. Streamlit Community Cloud is a server that stays online permanently and gives you a public https://…streamlit.app link — that's the entire difference between "I can see it" and "anyone can see it."

2.Step 1 — Create a GitHub Repository

  1. Go to github.com and sign in.
  2. Click the + icon (top right) → New repository.
  3. Give it a name, e.g. predictive-maintenance-app.
  4. Set visibility to Public. Streamlit Community Cloud's free tier deploys from public repos.
  5. Leave "Add a README" unchecked — you'll be pushing your own files in shortly.
  6. Click Create repository. GitHub will show you an empty repo with a URL like github.com/<your-username>/predictive-maintenance-app — keep this page open.

3.Step 2 — Install GitHub Desktop

  1. Go to desktop.github.com and download the installer for your OS (Mac or Windows).
  2. Install and open it, then sign in with the same GitHub account from Step 1 when prompted.
GitHub Desktop exists so you never have to type a single git command — every action in this guide (clone, commit, push) is a button click in this app.

4.Step 3 — Clone the Repository

  1. In GitHub Desktop: File → Clone Repository.
  2. Under the GitHub.com tab, find and select the repo you just created (predictive-maintenance-app).
  3. Choose a Local Path — a folder on your computer where the repo will live, e.g. Documents/predictive-maintenance-app.
  4. Click Clone. GitHub Desktop downloads the (currently empty) repo to that folder.

5.Step 4 — Copy Your App Files In

Using Finder/File Explorer, copy the contents of your class StreamlitApp folder directly into the local repo folder you just cloned (not the folder itself — the files should sit at the top level, alongside where .git lives).

predictive-maintenance-app/ ├── app.py
├── requirements.txt
├── rf_model.joblib
├── scaler.joblib
└── metadata_rfs.json
Check your file paths first. app.py must load files by relative name — joblib.load('rf_model.joblib') — never by an absolute path like /Users/you/Documents/.../rf_model.joblib. An absolute path only exists on your own laptop; Streamlit Cloud's servers don't have it, and the app will crash on load. (The class StreamlitApp/app.py already does this correctly — it's only something to double check if you've edited the file.)

6.Step 5 — Commit & Push (No Command Line)

  1. Switch back to GitHub Desktop. It automatically detects every new file you copied in, listed under "Changes."
  2. At the bottom left, type a commit message, e.g. Add Streamlit app files.
  3. Click Commit to main.
  4. Click Push origin (top toolbar) to upload the commit to GitHub.
  5. Refresh the repo's page on github.com — your files should now be visible there.
This is the exact same commit → push workflow used in the command line (git add, git commit, git push) — GitHub Desktop just wraps it in buttons.

7.Step 6 — Deploy on Streamlit Community Cloud

  1. Go to share.streamlit.io and sign in with GitHub.
  2. Click Create app (or New app).
  3. Choose "Deploy a public app from GitHub".
  4. Pick your repository (predictive-maintenance-app), branch (main), and the main file path — app.py.
  5. Click Deploy. Streamlit Cloud clones your repo, reads requirements.txt, installs those packages, and starts your app — the build log streams live on screen and typically finishes in 1–3 minutes.
  6. Once it says your app is live, you'll get a public URL: https://<something>.streamlit.app. That link works for anyone, anywhere — no login required to view it.

8.Step 7 — Update Your Live App Later

Your live app is wired directly to the main branch of your GitHub repo. To change anything about the app after deployment:

  1. Edit the file locally (e.g. app.py) in the cloned folder.
  2. In GitHub Desktop: commit the change, then push.
  3. Streamlit Cloud detects the new push automatically and redeploys within a minute or two — no need to visit share.streamlit.io again.

9.Troubleshooting

SymptomCauseFix
ModuleNotFoundError in the build logA package app.py imports isn't listed in requirements.txtAdd the missing package name (one per line) to requirements.txt, commit, push — Streamlit Cloud reinstalls automatically.
FileNotFoundError for a .joblib/.json fileAn absolute local path was left in the code, or the file wasn't actually pushed to GitHubUse relative filenames only (Section 5); confirm the file is visible in the GitHub repo's file list on github.com.
Push rejected / "file too large"GitHub blocks individual files over 100 MB (and warns at 50 MB) — some trained model files get close to thisRe-save the model with a lighter compression (joblib.dump(model, 'f.joblib', compress=3)), or reduce model size (e.g. fewer trees / lower max_depth).
App builds but shows a blank/grey pageUsually a runtime exception thrown after the page partially loadsOpen the app on share.streamlit.io and check the "Manage app" logs panel — it shows the same traceback you'd see locally.
Repository not showing up in Streamlit Cloud's pickerStreamlit's GitHub connection hasn't been granted access to that repoOn share.streamlit.io, go to Settings → Linked accounts → GitHub → "Manage access" and grant it.

10.Summary

The whole idea, in one paragraph

A Streamlit app that only runs on your laptop isn't deployed yet — it's just running. Deployment means putting the exact same files somewhere that stays online without your laptop: push the StreamlitApp folder to a public GitHub repo (via GitHub Desktop, no command line needed), then point Streamlit Community Cloud at that repo's app.py. Streamlit Cloud handles the server, the Python environment, and the public URL — every future update is just another commit and push away.
