Boosting & AdaBoost

Random Forest built many trees independently and averaged them. Today: the opposite instinct — build trees one after another, each one existing purely to fix what the last one got wrong. Ensemble Learning's second big idea, worked by hand on a 5-row loan dataset all the way to a final vote.

Recap: Bagging, Random Forest, Proximity Matrix

Random Forest = Bootstrapping + Aggregation. A single Decision Tree is highly sensitive to its exact training data — one specific structure, one perspective. Bagging's fix: randomness in both rows (bootstrapping) and columns, build multiple trees, aggregate their results. The trees are built independently — none of them know what the others are doing. (The Proximity Matrix — how often two rows land in the same leaf across the whole forest — was last session's closing idea, and stays exactly as covered then.)

Boosting, Defined

Weak Model 1 → Weak Model 2 (fixes Weak Model 1's mistakes) → Weak Model 3 (fixes what's still wrong) → … Several weak models, built sequentially, become one strong model. Each new model exists specifically to correct the previous ensemble's errors.

Weak Learners: An Army of Stumps

AdaBoost's weak learner is a stump — a Decision Tree with exactly one split, one column, two leaves. Deliberately weak: barely better than a coin flip on its own. Every column gets its own candidate stump; whichever one has the highest Information Gain becomes the first weak learner.

Amount of Say (α)

α = ½ ln( (1 − error) / error ) For error = 0.20: α₁ = ½ ln(0.8/0.2) = ½ ln(4) ≈ 0.693. Every stump earns a vote weight based on how accurate it was — not "trust everyone equally."

At error = 0.5 (a coin flip), α is exactly 0 — that stump earns zero say. Below 0.5, α is positive. Above 0.5 — a stump wrong more often than right — α goes negative, inverting its vote (being reliably wrong is just as informative as being reliably right).

Reweighting

Misclassified rows get multiplied by e+α (bigger); correctly classified rows get multiplied by e−α (smaller), then everything is renormalized to sum to 1.

Weighted error = 0.125 + 0.125 = 0.25 → α₂ = ½ ln(0.75/0.25) = ½ ln(3) ≈ 0.549. Applicant #2 — last round's problem — is fixed. The cost: two previously-easy rows (#3, #5) are missed instead. That trade-off is what Boosting is constantly making.

Round 3 — Stump 3: "Debt = Low?"

Reweight again using α₂, resample, fit a third stump. This one misses only applicant #1 — whose weight, after two rounds of shrinking (correct both times), has fallen to just 1/12 ≈ 0.083.

Error₃ = 1/12 ≈ 0.083 → α₃ = ½ ln(0.917/0.083) = ½ ln(11) ≈ 1.199 Tiny error → huge α. Stump 3 is nearly always right on the data it was shown, so it earns an outsized vote — almost double Stump 1's, and more than double Stump 2's.

The Final Vote

final(x) = sign( Σ αₜ hₜ(x) ) Encode Approve as +1, Reject as −1. Every stump's vote gets scaled by its own α before summing.

Rapid-Fire FAQ

  1. Why "Adaptive"? Misclassified samples get more weight — the algorithm adapts to its own mistakes, round by round.
  2. What's the weak learner? A stump — a Decision Tree with a single split.
  3. Can it use deeper trees? Yes, but it causes overfitting. Stumps are the standard choice on purpose.
  4. How does it re-focus each round? Exponential increase for wrong rows, exponential decrease for right ones.
  5. How's the final prediction made? sign(Σ αₜ hₜ(x)) — every stump's vote, weighted by its own amount of say.
  6. Sensitive to outliers? Yes — an outlier gets misclassified repeatedly, its weight balloons, and later stumps can over-focus on it.
  7. Can it overfit? Yes — enough rounds chasing enough noisy points will eventually memorize them.
