Recap · The Salary Network

One input, two hidden neurons, one output

Experience x → two hidden neurons (each an affine step + ReLU) → an output neuron that mixes them. ŷ = v₁·h₁ + v₂·h₂ + c, where h₁ = ReLU(w₁x + b₁) and h₂ = ReLU(w₂x + b₂).

x = experience → h₁, h₂ (ReLU) → ŷ = salary
Hyperparameters we choose: the number of hidden neurons / layers and the choice of non-linearity (ReLU here). The weights themselves are learned — that's today's story.
The Forward Pass

Make a guess for x = 5 years

Plug the current weights through the network, left to right. With w₁=4, b₁=20, w₂=1, b₂=−3, v₁=1, v₂=10, c=0:

ŷ = 1·(40) + 10·(2) + 0 = 60  (i.e. ₹60k)

The Loss · "How wrong were we?"

L = ½(ŷ − y)² = 12.5

The real salary for 5 years is ₹65k, but we guessed ₹60k. The loss turns that gap into a single number we can shrink:

L = ½ (60 − 65)² = ½ (−5)² = ½ · 25 = 12.5
Why squared, and why halved? Squaring makes the error always positive and punishes big misses more. The ½ is a convenience — it cancels the 2 when we differentiate, keeping the math clean. This is MSE (mean squared error) for a single row.
Loss vs. Metric · Don't Confuse Them

The model learns from the loss, not the metric

A metric (accuracy, F1) is a human-readable score. But accuracy is a step function — flat, then a jump — so its gradient is zero almost everywhere. You can't descend a staircase of zeros.

Loss
Differentiable by design (MSE, log-loss). The optimizer can compute its slope and follow it downhill.
Metric
Human quantification of performance (Accuracy, F1). Often not differentiable — can't train on it directly.
Two Directions of Information Flow

Forward to guess, backward to learn

Input→Hidden→Output→Loss ✓
Input-side grads←Hidden grads←Output grads←Loss
Forward pass: data flows in, a prediction and loss come out. Backward pass (backpropagation): the loss flows back, handing each parameter its share of the blame — its gradient.
What Is a Gradient?

"If I nudge this one weight, how does the loss change?"

A gradient ∂L/∂w is the slope of the loss with respect to one parameter, holding the others fixed. Its sign tells you which way to move, its size tells you how much this parameter is to blame.

+ gradient → increasing this param increases loss → so decrease it.
− gradient → increasing this param decreases loss → so increase it.
Why the loss must be differentiable
Gradients come from differentiation. Accuracy isn't differentiable — it can't "go through." The loss is chosen precisely so it can.
The Chain Rule · One Weight's Blame

∂L/∂w₁ = ∂L/∂ŷ · ∂ŷ/∂h₁ · ∂h₁/∂z₁ · ∂z₁/∂w₁

The error reaches w₁ by passing back through every step it took forward. Each factor answers one small question:

💰

∂L/∂ŷ

How does loss change w.r.t. the predicted salary? = ŷ − y = −5.

🔗

∂ŷ/∂h₁

How does the output change w.r.t. this hidden neuron? = v₁ = 1.

⚡

∂h₁/∂z₁

ReLU's slope: 1 if z₁>0, else 0. Here z₁=40 → 1.

📊

∂z₁/∂w₁

How does the weighted sum change w.r.t. w₁? = x = 5.

∂L/∂w₁ = (−5)·(1)·(1)·(5) = −25

The Training Loop

Guess → Measure → Blame → Nudge

Input data→ Forward pass→ Loss→ Backprop→ Optimizer step

These five steps are one iteration. Do them over and over and the loss shrinks until the predictions match reality. In PyTorch it's literally five lines inside a for loop.

Epoch vs. Batch vs. Iteration

Three words people mix up

🔁

Epoch

One complete pass through the entire dataset. 1000 rows seen once = 1 epoch.

📦

Batch

A chunk of rows processed together before one update. 1000 rows in batches of 100 = 10 batches.

👣

Iteration

One optimizer step — one batch's worth. 10 batches → 10 iterations = 1 epoch.

Per-row (batch=1): sensitive, every row's pattern counts — SE = ½(ŷ−y)². Mini-batch: smoothed over e.g. 100 rows. Full-batch: one update per epoch over all N rows — MSE = (1/2N)Σ(ŷ−y)². Our tiny SalaryNet uses full-batch (all 11 rows at once).
In PyTorch · The Five Lines

The loop, in real code

PyTorch computes every gradient for you — loss.backward() does the entire chain rule across the whole network. You never hand-derive it again.

zero_grad()
"Factory reset" — clears last step's gradients so they don't accumulate.
# one epoch = one pass over X
for epoch in range(3000):
    pred = model(X)              # forward
    loss = loss_fn(pred, y)      # measure

    optimizer.zero_grad()        # reset
    loss.backward()              # backprop
    optimizer.step()             # nudge

loss_fn   = nn.MSELoss()
optimizer = torch.optim.Adam(
    model.parameters(), lr=0.02)
Save the Trained Brain

Ship the state_dict, not the object

torch.save(model.state_dict(), "salary_net.pth")   # just the learned weights

We save only the weights (the state_dict), not the whole Python object. The app rebuilds the same SalaryNet class and pours these numbers back in. This is the portable, standard way to ship a model — a few KB file that any machine with model.py can load.

✓ Trained once in Jupyter → saved to a file → loaded forever after, no retraining.
Serve It · Flask

From a file to a website & API

A trained model in a file helps no one. Flask loads the model once at startup and answers requests on port 8080 — a web form at /, a JSON API at /api/predict, and /health for the cloud to check it's alive.

model = load_model()   # once, at startup

@app.route("/api/predict",
           methods=["POST"])
def predict_api():
    exp = request.get_json()["experience"]
    x = torch.tensor([[float(exp)]])
    with torch.no_grad():
        s = model(x).item() * 1000
    return jsonify(salary=s)
