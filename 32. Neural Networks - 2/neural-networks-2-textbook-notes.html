1.The Forward Pass

The forward pass runs the current weights through the network, left to right, to produce a prediction. For SalaryNet (1 input → 2 hidden ReLU neurons → 1 output):

h₁ = ReLU(w₁x + b₁),   h₂ = ReLU(w₂x + b₂),   ŷ = v₁h₁ + v₂h₂ + c With w₁=4, b₁=20, w₂=1, b₂=−3, v₁=1, v₂=10, c=0 and x=5: h₁=ReLU(40)=40, h₂=ReLU(2)=2, ŷ = 40 + 20 + 0 = 60.

2.The Loss, and Why It Must Be Differentiable

The loss collapses "how wrong is the prediction" into one number to minimise. For regression we use squared error:

L = ½(ŷ − y)²  →  L = ½(60 − 65)² = 12.5 Squaring removes sign and penalises large misses super-linearly. The ½ cancels the exponent's 2 on differentiation, keeping ∂L/∂ŷ = (ŷ − y) clean.
Loss vs. metric. Training minimises a loss (MSE, cross-entropy) — chosen to be smooth and differentiable so an optimizer can follow its slope. A metric (Accuracy = (TP+TN)/(TP+TN+FP+FN), F1) is for humans to read; accuracy is piecewise-constant, so ∂Accuracy/∂w is zero almost everywhere and cannot drive learning. "That which is not differentiable cannot go through" backprop.

3.Gradients: The Core Idea

A gradient ∂L/∂θ answers: how does the loss change when I make a small change to parameter θ, holding everything else fixed?

  • Positive gradient → increasing θ increases loss → move θ down.
  • Negative gradient → increasing θ decreases loss → move θ up.
  • Magnitude → how much this one parameter is responsible for the current error.

The model "learns by parameter update using (1) the loss." Gradients are produced by differentiation, which is precisely why the loss is designed to be differentiable (Section 2).

4.Backpropagation & the Chain Rule

Backpropagation sends the loss backwards through the network, computing each parameter's gradient by multiplying the local derivatives along the path the signal took forward — the chain rule. For a first-hidden-layer weight:

∂L/∂w₁ = ∂L/∂ŷ · ∂ŷ/∂h₁ · ∂h₁/∂z₁ · ∂z₁/∂w₁ Read right-to-left as the error flows back: how the weighted sum z₁ changes with w₁ (= x), how h₁ changes with z₁ (ReLU′), how ŷ changes with h₁ (= v₁), how L changes with ŷ (= ŷ−y). Each factor is one link in the chain.

Output-layer parameters are shorter chains: ∂L/∂v₁ = ∂L/∂ŷ · ∂ŷ/∂v₁ = (ŷ−y)·h₁. The key property: backpropagation measures the contribution of each parameter towards the loss, efficiently, in one backward sweep — no matter how many layers.

ReLU's derivative is 1 for z > 0 and 0 for z < 0. So a hidden neuron whose pre-activation is negative (its ReLU output is 0) passes zero gradient back through that path — it is "switched off" for that example, both forward and backward.

5.The Worked Example, End to End

Forward gave ŷ = 60, y = 65, so ∂L/∂ŷ = ŷ − y = −5. Propagating back (ReLU′ = 1 since both z₁=40 and z₂=2 are positive):

ParameterChainGradient
w₁(−5)(v₁=1)(1)(x=5)−25
b₁(−5)(1)(1)(1)−5
w₂(−5)(v₂=10)(1)(x=5)−250
b₂(−5)(10)(1)(1)−50
v₁(−5)(h₁=40)−200
v₂(−5)(h₂=2)−10
c(−5)(1)−5

With η = 0.0001, each θ_new = θ_old − η·grad gives w₁=4.0025, b₁=20.0005, w₂=1.025, b₂=−2.995, v₁=1.02, v₂=10.001, c=0.0005. Re-running the forward pass: h₁=40.013, h₂=2.13, ŷ ≈ 62.12 — the prediction moved from 60 toward the target 65, and the loss dropped. Three thousand such steps converge it onto ₹65k.

6.Gradient Descent & the Learning Rate

θnew = θold − η · ∂L/∂θ η (eta) is the learning rate — the step size. Too small: training crawls. Too large: steps overshoot the minimum and the loss can oscillate or diverge. It is the most important hyperparameter to tune.

Gradient descent repeatedly takes a step opposite to the gradient (downhill on the loss surface). Each full "forward → loss → backprop → step" is one update.

7.Optimizers: SGD, Momentum, Adam

OptimizerIdeaNotes
SGDPlain update θ − η·grad, on each batch.Simple; sensitive to η and to feature scaling.
SGD + MomentumAccumulate a velocity of past gradients to push through flat spots.Faster, smoother descent than plain SGD.
AdamPer-parameter adaptive step sizes from running averages of the gradient and its square.The common default; robust across problems. Used in SalaryNet (lr=0.02).

(The deeper comparison of gradient-descent variants is the next session's topic; here Adam is simply "the method that decides how big each weight's nudge is.")

8.Epoch, Batch, Iteration

TermMeaningExample (1000 rows, batch 100)
EpochOne full pass over the entire dataset.All 1000 rows seen once.
BatchRows processed together before one update.100 rows per batch → 10 batches.
IterationOne optimizer step (one batch).10 iterations = 1 epoch.
Batch size is a bias/variance-of-the-gradient knob. Batch=1 (stochastic): noisy, sensitive updates where every row's pattern counts — SE = ½(ŷ−y)². Mini-batch (e.g. 100): a smoothed estimate, the practical default. Full-batch: one exact update per epoch over all N rows — MSE = (1/2N)Σ(ŷ−y)². SalaryNet trains full-batch on all 11 rows.

9.PyTorch: Autograd & the Training Loop

Frameworks like PyTorch (and TensorFlow) run on GPUs and provide autograd: loss.backward() computes every gradient in Section 5 automatically by recording the forward operations. You never hand-derive the chain rule again.

loss_fn   = nn.MSELoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.02)

for epoch in range(3000):
    pred = model(X)              # forward pass
    loss = loss_fn(pred, y)      # compute loss
    optimizer.zero_grad()        # clear last step's grads (they accumulate otherwise)
    loss.backward()              # backprop: fills every .grad
    optimizer.step()             # apply θ = θ - η·grad
Why zero_grad()? PyTorch accumulates gradients into .grad by default (useful for some advanced cases). Without clearing them each step, this batch's gradients would add on top of last batch's — a "factory reset" before each backward() keeps the step correct.

10.Saving & Serving the Model

Save only the learned weights (the state_dict), not the whole object — portable and small:

torch.save(model.state_dict(), "salary_net.pth")   # save

# later, in the app:
model = SalaryNet()
model.load_state_dict(torch.load("salary_net.pth", map_location="cpu"))
model.eval()                                        # inference mode

A Flask app loads the model once at startup and serves predictions on port 8080 (web form /, JSON /api/predict, /health). Wrapping inference in with torch.no_grad(): skips gradient tracking — faster and lighter, since we're predicting, not training. From there: push to GitHub, create a GCP e2-small VM, open port 8080 (firewall rule + network tag in Cloud Shell), SSH in, install git & venv, clone and run. The full step-by-step is in the GCP Deployment Guide.

11.Summary

The whole idea, in one paragraph

A network learns by repeating a loop: a forward pass produces a prediction, a differentiable loss measures the error, backpropagation applies the chain rule to give every parameter its gradient (its share of the blame), and an optimizer step nudges each parameter downhill by η·gradient. One pass over the data is an epoch; one step over a batch is an iteration. PyTorch's autograd computes all gradients from loss.backward(), Adam decides each nudge, and once trained we save the state_dict, serve it with Flask on port 8080, and deploy it to a Google Cloud VM for the world to use.
