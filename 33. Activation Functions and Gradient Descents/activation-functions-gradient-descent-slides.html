Recap · Affine Is Just a Line

Whatever W and b you pick, a line stays a line

z = Wx + b (= mx + c) is an affine transform: W scales / rotates / reflects, b shifts up or down. Points stay on the same line; parallel lines stay parallel. Stack as many affine layers as you like and they collapse into one line — that's Linear Regression, not a deep network.

Polynomial trick: feeding x², x³ as new inputs into mx+c gives m₁x² + m₂x +c — non-linear in the input, but still linear in the parameters. We want a model that's genuinely non-linear.
Part III · Why an Activation Function?

It activates non-linearity

The weighted sum combines information; the activation function is what transforms the result. Put a non-linear function f after each hidden neuron's affine step and the network can finally bend — fitting the "salary rises faster later" kink a straight line never could.

A layer with many neurons = a hidden layer. The non-linear f applied after it = the activation function. No activation → no depth, just one big line.

ReLU — Rectified Linear Unit
max(0, z). Negatives become 0, positives pass through. The default hidden-layer activation.
ReLU & the Dead-Neuron Problem

ReLU turns negatives to 0 — but dead is dead

ReLU(z) = max(0, z). Clean and cheap, but if a neuron's z stays negative it outputs 0 and passes 0 gradient back — it's "dead" and may never recover. Leaky ReLU fixes this with a small slope for z < 0.

Optimisation · Rolling Downhill

θnew = θold − η · ∇J

The cost J(θ) = (1/N)Σ ½(y−ŷ)² is a bowl (convex for this squared loss). The gradient ∇J points uphill; we step the opposite way. The learning rate η sets the step size — and it matters enormously.

Why squared loss? (1) squaring removes the sign of the error; (2) it makes the loss surface convex — one global bottom, easy to roll into.
η too high → steps overshoot, bounce across the valley, never settle ("keep shuffling, not descending").
η too low → tiny safe steps, slowly but surely toward the optimum. Important to keep η low-ish.
η is a fixed hyperparameter
e.g. 0.001 or 0.00001. A single fixed value for all parameters — which is exactly the limitation adaptive methods (Section 4) fix.
The Training Loop, Again

Forward → Loss → Backprop → Update → Repeat

∇J is the vector of every parameter's gradient: [∂J/∂w₁, ∂J/∂b₁, … ∂J/∂b₃]. Backpropagation fills it in one sweep; the optimizer applies the update; repeat N times until the loss stops falling. The open question for the rest of today: how many rows do we look at before each update?

Full-Batch Gradient Descent

Look at all rows, then take one step

10,000 employees → one forward pass over all of them → MSE over all 10,000 → one gradient → one parameter update. Repeat for the next epoch.

✅

Advantage

The gradient reflects the full training set — a smooth, accurate estimate of the true descent direction.

⚠️

Disadvantage

One update needs the whole dataset in memory, and the loss is too smooth — slow, and can stall in flat regions.

Stochastic GD (SGD)

One row, one update

10,000 rows → 10,000 updates per epoch, one employee at a time. Loss per step is just ½(yᵢ − ŷᵢ)².

✅ Frequent, inexpensive updates — fast to react, every row's pattern counts.
⚠️ Noisy gradients — the path to the bottom zig-zags because each step trusts a single row.
Mini-Batch GD

A handful of rows per step

Batch size 1024 / 128 / 100 / 10… rows, randomly drawn. 10,000 rows in batches of 1,000 → 10 updates per epoch.

The practical default: smoother than SGD, lighter than full-batch. Batch size is itself a hyperparameter.

The Next Step · Adaptive Optimisers

A fixed η isn't good enough

All three variants above still use one fixed learning rate. The next improvement: let the step size adapt — per parameter, over time — so training is more calibrated and robust.

📉

Adaptive Descent

Shrink the step for parameters that have moved a lot; grow it for those that have barely moved.

⚡

Adam

Combines momentum (a running average of gradients) with per-parameter adaptive rates. The common default — and where we go next.
