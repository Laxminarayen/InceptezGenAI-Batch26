Activation Functions & Gradient Descent

The activation function is the only source of non-linearity in a network; its shape decides whether gradients flow or die. Gradient descent is how the network moves downhill on its loss; its batch size decides how smooth and how frequent each step is. This chapter catalogues both and explains the trade-offs that lead to Adam.

1.Why Activation Functions Exist

A neuron's pre-activation z = Wx + b is affine — a line/plane with W as slope and b as intercept. Affine maps have two properties: points stay on the same line, and parallel lines stay parallel. Crucially, composing affine maps gives another affine map: W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂). So any stack of purely linear layers collapses into a single line — no matter how deep.

a = f(Wx + b),   f non-linear The activation f is the only thing that breaks the collapse. The weighted sum combines information; f transforms it, letting the network represent curves, kinks, and interactions a single line cannot.
Polynomial regression is still linear. y = w₁x + w₂x² is non-linear in x but linear in the parameters w₁, w₂ (treat x² as a feature). It is fit by the same least-squares machinery and is a linear model — unlike a network, which is non-linear in its parameters precisely because of f.

2.ReLU & the Dead-Neuron Problem

ReLU(z) = max(0, z)  ;  ReLU′(z) = 1 if z > 0, else 0 Range [0, +∞). The default hidden-layer activation: cheap, sparse, and — for z > 0 — passes gradients through undiminished, which avoids the vanishing-gradient issue sigmoids suffer.

The dead-neuron problem: because ReLU′(z) = 0 for z < 0, a neuron stuck in the negative region outputs 0 and receives 0 gradient. If a large update pushes its weights so that z is negative for every input, it can never update again — it is permanently "dead." In practice a fraction of ReLU units die during training; the fixes in Section 3 address exactly this.

3.Leaky ReLU & ELU

LeakyReLU(z) = z if z > 0, else 0.01·z Range (−∞, +∞), non-saturating. The small positive slope on the negative side means ReLU′ is never exactly 0, so gradients keep trickling and dead neurons can recover.
ELU(z) = z if z > 0, else α(eᶻ − 1) Range (−α, +∞). A smooth exponential curve for negatives that saturates softly toward −α. α controls the magnitude of the negative floor. Zero-centred-ish outputs can speed convergence versus ReLU.

Worked contrast (z = x − 3 at x = 2, so z = −1; downstream salary = 30 + 10·h): ReLU gives h = 0 → ₹30.0k (the unit contributes nothing), while Leaky ReLU gives h = −0.01 → ₹29.9k (it still carries a small signal, and a non-zero gradient).

4.Sigmoid & Tanh

σ(z) = 1 / (1 + e⁻ᶻ)  ;  range (0, 1) Squashes to a probability. Values of σ(x−3): x=1→0.119, x=2→0.269, x=3→0.500, x=4→0.731, x=5→0.881. Used as a binary-classification output (interpret as P(class=1)); poor as a deep hidden activation because it saturates.
tanh(z) = (eᶻ − e⁻ᶻ)/(eᶻ + e⁻ᶻ)  ;  range (−1, 1) A zero-centred cousin of sigmoid. Zero-centring makes its outputs easier for the next layer to work with, so historically it was preferred over sigmoid for hidden layers — but it still saturates at both ends.
A sigmoid output cannot represent a continuous prediction (it's bounded to (0,1)); it can only be an output for binary classification. For continuous targets the output neuron is left linear (no activation), as in SalaryNet.

5.Saturation, Range & Vanishing Gradients

Saturation is where an activation's curve goes flat — its derivative approaches 0. In a flat region, backprop multiplies by a near-zero slope, so almost no gradient reaches earlier layers: the vanishing-gradient problem. Sigmoid and tanh saturate at both ends; ReLU saturates (hard) only for z < 0; Leaky ReLU does not saturate; ELU saturates softly for z < 0.

6.Choosing an Activation

  • Hidden layers: start with ReLU. If you see many dead units or want smoother negatives, try Leaky ReLU or ELU.
  • Binary-classification output: sigmoid (one probability).
  • Multiclass output: softmax (a probability distribution — met in Logistic Regression, Class 26).
  • Regression output: no activation (linear), so the network can output any real number.

7.Gradient Descent & the Learning Rate

J(θ) = (1/N) Σᵢ ½(yᵢ − ŷᵢ)²  ;  θnew = θold − η·∇J(θ) ∇J = [∂J/∂w₁, ∂J/∂b₁, …] is the gradient (rate of change) w.r.t. every parameter. η is the learning rate.

Why squared loss? It removes the sign of the error, and it makes the cost surface convex for a linear model — a single global minimum to descend into. The learning rate is the critical hyperparameter: too large and the updates overshoot and oscillate across the valley without settling; too small and training is correct but painfully slow. A single fixed η applied to every parameter is a real limitation — different parameters may need different step sizes.

8.Full-Batch, SGD & Mini-Batch

Mini-BatchB (e.g. 32–1024)N / B (e.g. 10)The practical default — smoother than SGD, lighter than full-batch. B is a hyperparameter.

SGD's loss for a single example is ℓ = ½(yᵢ − ŷᵢ)²; mini-batch averages over B rows; full-batch averages over all N. The noise in SGD is not purely bad — it can help escape poor flat regions — but mini-batch is the usual balance of speed, memory, and stability.

9.Toward Adaptive Optimisers (Adam)

All three variants above still use one fixed η. Adaptive methods remove that constraint:

  • Momentum — accumulate a running "velocity" of past gradients to push through flat spots and dampen oscillation.
  • Adaptive learning rates (AdaGrad / RMSProp) — give each parameter its own effective step, shrinking it for parameters that have already moved a lot.
  • Adam — combines both: momentum (first moment) + per-parameter adaptive scaling (second moment). It's the common default and makes training far less sensitive to the initial η. (The deep dive is the next session.)

10.In PyTorch

from torch import nn

# activations as layers or functions
nn.ReLU()            # max(0, z)
nn.LeakyReLU(0.01)   # small negative slope
nn.ELU(alpha=1.0)    # smooth negatives
nn.Sigmoid()         # (0,1) — binary output
nn.Tanh()            # (-1,1)

# optimisers — the batch size lives in the DataLoader, not the optimiser
opt = torch.optim.SGD(model.parameters(), lr=0.01)          # (mini-batch) SGD
opt = torch.optim.Adam(model.parameters(), lr=0.001)        # adaptive (Section 9)
loader = DataLoader(dataset, batch_size=64, shuffle=True)   # batch_size → full/mini/SGD
Full vs. mini vs. SGD is set by batch_size in the DataLoader: batch_size = len(dataset) is full-batch, 1 is pure SGD, anything in between is mini-batch. The optimiser (SGD, Adam) is a separate choice.

11.Summary

The whole idea, in one paragraph

An activation function is the only non-linearity in a network — without it, any depth collapses to a single line. ReLU (max(0,z)) is the hidden-layer default but can create dead neurons; Leaky ReLU and ELU fix that with a non-zero negative branch; sigmoid and tanh squash to bounded ranges and saturate at both ends, which makes sigmoid good for a binary output but poor as a deep hidden unit. Learning happens by gradient descent, θ ← θ − η∇J, where the learning rate η is the make-or-break hyperparameter. How many rows we use per update defines the variant — full-batch (exact, heavy), SGD (noisy, frequent), or mini-batch (the balanced default) — and because a single fixed η is limiting, the next step is adaptive optimisers like Adam.
