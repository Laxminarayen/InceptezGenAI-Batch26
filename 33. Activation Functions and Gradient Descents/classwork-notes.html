Revision: External vs. Internal IPs

An IP address is a unique address used to identify a machine. An internal (private) IP identifies a server within a private network — your laptop at home on the LAN behind Wi-Fi. An external (public) IP identifies your network on the internet (assigned by your ISP). Special addresses: 0.0.0.0 (bind to all interfaces), 127.0.0.1 (localhost), and private ranges. This ties back to last session's GCP deployment — the app binds 0.0.0.0:8080 and we reach it on the VM's external IP.

Recap: Rule-Based → ML → Deep Learning, and the Neuron

Rule-Based AI: humans write rules, data follows. Machine Learning: data arrives and rules are learned from the data. Deep Learning: automatically learns "multiple levels of representation" by itself (traditional ML uses engineered features handcrafted by us). A neuron computes a weighted sum z = w₁x₁ + w₂x₂ + w₃x₃ + b; weights control the influence of inputs, bias shifts the neuron's output / baseline (threshold). z = Wx + b is an affine transform (= mx + c): W scales/rotates/reflects, b translates. Whatever W and b you pick, a line stays a line — and stacking affine layers just gives another line.

Part III: Why Do We Need an Activation Function?

Activation function ⟹ activates non-linearity The weighted sum combines information; the activation function is what transforms the result. Without it, a deep stack collapses to one linear model.

A layer with many neurons is a hidden layer; the non-linear function applied after it is the activation function. (Polynomial aside: feeding x² as a new input into mx+c is non-linear in the input but still linear in the parameters — still a linear model.)

Activation Function 1: ReLU

ReLU(z) = max(0, z) Rectified Linear Unit. Negative inputs → 0; positive inputs pass through unchanged. Range [0, +∞).

What is ReLU doing? Turning negative values into zeros. The dead-ReLU problem: a neuron whose z stays negative outputs 0 and passes 0 gradient back — its gradient can become 0 permanently, so it never recovers ("dead"). What if we don't want negatives to become 0?

Activation Function 2: Leaky ReLU

f(z) = z if z > 0,   0.01·z if z ≤ 0 A non-saturating activation — the small 0.01 slope on the negative side keeps a trickle of gradient flowing, fixing the dead-neuron problem.

Worked example (z = x − 3, salary = 30 + 10·h at x = 2):

Activation Function 3: Sigmoid — When You Want Probability-Like Values

Instead of "how much salary," suppose we estimate eligibility for a ₹10,000 promotion bonus from experience — a probability. The sigmoid squashes any real number into (0, 1):

σ(z) = 1 / (1 + e⁻ᶻ) With h₂ = σ(x − 3):

Example: Ŝ = 20 + 5x + 10·h₂ at x = 5 → 20 + 25 + 10·(0.881) = 53.81. The sigmoid saturates at both ends (flat for very large/small z → vanishing gradients), so it cannot be an output for continuous prediction — but it can be used as the output for binary classification (0 or 1).

Activation Function 4: ELU, and Tanh

ELU(z) = z if z > 0,   α(eᶻ − 1) if z ≤ 0 Exponential Linear Unit. α controls the magnitude of the negative floor; smooth curve for negatives, bottoming out near −α. A "partially saturating" option.

Tanh squashes to (−1, 1), zero-centred, and also saturates at both ends. The negative-side "options": ReLU zeros it, Leaky leaks it (0.01z), ELU curves it (α(eᶻ−1)).

Part IV: Optimisation — Gradient Descent & the Learning Rate

For the 2-neuron net, θ = [w₁, b₁, w₂, b₂, w₃, w₄, b₃]. The cost function averages the loss over all rows:

J(θ) = (1/N) Σᵢ ℓ(f_θ(xᵢ), yᵢ),   with   ℓ = ½(y − ŷ)² Why squared loss? (1) to remove the sign of the error; (2) the surface is convex — one global minimum, easy to roll into.

The gradient ∇J is the vector of every parameter's rate of change [∂J/∂w₁, ∂J/∂b₁, …]. The update:

wnew = wold − η · (∂J/∂w),   bnew = bold − η · (∂J/∂b) η (learning rate) is chosen by us — a fixed hyperparameter (e.g. 0.001, 0.00001).
Learning rate matters enormously. η too high → the steps keep shuffling across the valley and never descend. η too low → slow but sure descent toward the optimum. Important to keep it low-ish. A single fixed η for all parameters is the limitation that adaptive optimisers fix.

Types of Gradient Descent

Full-Batch Gradient Descent

All rows → one forward pass → MSE over everything → one gradient → one parameter update, then repeat. For 10,000 employees: forward pass → MSE → gradients → update, as one step.

  • Advantage: the gradient represents the full training sample (loss is an average over all samples) — accurate, smooth direction.
  • Disadvantage: one update needs a lot of memory, and the loss is too smooth (can stall).

Stochastic Gradient Descent (SGD)

Sample = 10,000 rows → 10,000 updates per epoch, one employee at a time. Loss per step ℓ = ½(yᵢ − ŷᵢ)².

  • Advantage: frequent, inexpensive updates.
  • Disadvantage: noisy gradients (each step trusts a single row, so the path zig-zags).

Mini-Batch Gradient Descent

Batch size = 1024 / 128 / 100 / 10 / … ; samples in a batch are randomly taken. 10,000 rows in batches of 1,000 → 10 updates per epoch. The practical default — smoother than SGD, lighter than full-batch.
