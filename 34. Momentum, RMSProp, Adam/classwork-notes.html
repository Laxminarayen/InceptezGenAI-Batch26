Momentum, RMSProp & Adam

A fixed learning rate reacts only to the current, noisy gradient. Today we give the optimizer a memory — built from one idea, the EWMA — and turn it into Momentum, RMSProp, and their combination Adam. Then we classify handwritten MNIST digits with a neural network.

Recap: The Loss Surface & Plain SGD

For the 2-neuron net, θ = [w₁, w₂, w₃, w₄, b₁, b₂, b₃] — 7 parameters, so the loss surface lives in 7+1 = 8 dimensions. ∂J/∂w₁ involves the other parameters as well. Loss per row ℓ = ½(yᵢ − ŷᵢ)²; cost J = (1/N)Σ ℓ over all rows (mini-batch). SGD, full-batch, and mini-batch all take the same step, wnew = wold − η·gt — and because different mini-batches give different gradients, the path zig-zags.

Output-layer recap: sigmoid → (0,1) for binary; softmax → a distribution over [0,1,2,3] for multiclass; linear (−∞, ∞) for continuous. Continuous values → probabilities is the Logistic-Regression task.

Part 0: EWMA — Exponentially Weighted Moving Average

Deep learning is representation learning — neural networks are experts in deep representations. But first, a smoothing tool. Consider noisy ice-cream sales:

DayMonTueWedThuFriSatSun
Sales50524980515053

Simple 3-day moving average

Wed = (50+52+49)/3 = 50.33; Thu = (52+49+80)/3 = 60.33; Fri = (49+80+51)/3 = 60.00. Equal weight to all 3 days, abrupt forgetting.

EWMA — more weight to recent, less to old

EMA = 0.8·(previous EMA) + 0.2·(current value) Keep 80% of the previous estimate, incorporate 20% of the current value — a smooth, fading memory.
DayActualEMA = 0.8·prev + 0.2·current
Mon5050.00 (seed)
Tue520.8·50 + 0.2·52 = 50.40
Wed490.8·50.4 + 0.2·49 = 50.12
Thu800.8·50.12 + 0.2·80 = 56.096

The actual spiked to 80, but the smoothed value only rose to 56.1 — EWMA refuses to overreact to one noisy day. That smoothing is exactly what we'll apply to noisy gradients.

Part I: Gradient Descent with Momentum

Plain update: wnew = wold − η·gt → "just depends on the current value of ∂J/∂θ, and is not intelligent." Different mini-batches calculate very different gradients for w₁, w₂, so the descent oscillates. Apply the EWMA idea to the gradients:

mt = β·mt−1 + (1−β)·gt,   then   wnew = wold − η·mt mt is an EWMA of gradients (previous EWMA + current gradient) — "intelligent, previous-gradient-aware." A velocity that remembers the consistent direction.

Consistent directions reinforce and build speed; random zig-zags cancel out. Momentum helps with capturing a consistent direction. (Compare: wnew = wold − η·gt uses the current gradient; momentum uses mt, the gradient history.)

Part II: RMSProp (Root Mean Square Propagation)

Momentum captures direction, but now the step size has to be coordinated for each parameter — what if one parameter's gradients are usually very large while another's are small? RMSProp tracks an EWMA of squared gradients:

St = ρ·St−1 + (1−ρ)·gt² Squaring removes the sign and just keeps magnitude ("how big have this parameter's gradients been lately?").
wnew = wold − (η / √(St + ε))·gt ε is a small nudge to avoid dividing by 0. Big recent gradients → large St → divide by a big number → shrink the step; small gradients → grow it. The learning rate need no longer be fixed — it becomes an adaptive step, per parameter.

Part III: Adam = Adaptive Moment Estimation

Two ideas, combined: Momentum (EMA of signed gradients — direction) and RMSProp (EMA of squared gradients — scaling η). Adam keeps both memories:

wnew = wold − (η / √(vt + ε))·mt mt = EWMA of gradients (momentum, numerator); vt = EWMA of squared gradients (RMSProp, denominator); ε = small nudge to avoid ÷0. Direction and step size, handled together.
The default optimizer. Adam (and AdamW) is what you reach for first on most deep-learning problems — fast, stable, and forgiving of the initial learning rate. torch.optim.Adam(model.parameters(), lr=0.001).

Part IV: MNIST Image Classification with a Neural Network

MNIST = 28×28 greyscale images of handwritten digits 0–9. Load with torchvision.datasets.MNIST, transform to tensors, and batch with a DataLoader (batch_size=128). 60,000 training images ÷ 128 ≈ 469 updates per epoch.

784 → 128 → 10   (Cross-Entropy) Flatten 28×28 = 784 inputs → hidden layer of 128 neurons (ReLU) → 10 outputs (one per digit). CrossEntropyLoss turns the 10 scores into class probabilities. 
def make_model(activation="ReLU"):
    return nn.Sequential(
        nn.Flatten(),
        nn.Linear(28*28, 128),
        activation_choices[activation](),   # ReLU / Tanh / Sigmoid / LeakyReLU / ELU / GELU
        nn.Linear(128, 10)
    )

loss_fn   = nn.CrossEntropyLoss()           # categorical cross-entropy
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)

for images, labels in train_loader:
    pred = model(images)                    # forward pass over the batch
    loss = loss_fn(pred, labels)
    optimizer.zero_grad()                   # clear old gradients
    loss.backward()                         # backpropagation
    optimizer.step()                        # update weights

# accuracy: predictions = model(images).argmax(dim=1)

The notebook trains the same network with each optimizer — SGD, Momentum (SGD + momentum=0.9), RMSprop, Adam, AdamW — and also lets you swap the activation, so you can watch adaptive optimizers converge faster and steadier than plain SGD on real digits.
