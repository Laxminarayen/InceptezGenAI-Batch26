Momentum, RMSProp & Adam

Plain gradient descent trusts one noisy gradient per step. Modern optimizers give it a memory — an exponentially weighted moving average of gradients (Momentum), of squared gradients (RMSProp), or of both (Adam). This chapter builds all three from the EWMA and connects them to the MNIST classifier.

1.The Problem: Noisy Gradients

With mini-batch (or stochastic) gradient descent, each update wnew = wold − η·gt uses the gradient from one batch. Different batches give different gradients for the same weight, so the raw gradient gt is noisy: it reflects only the current value and is "not intelligent." On an elongated loss valley the descent zig-zags across the steep direction while crawling along the gentle one — many wasted steps. The remedy is to stop trusting a single reading and average it over time.

2.EWMA — Exponentially Weighted Moving Average

EMAt = β·EMAt−1 + (1−β)·xt β is the weight on the accumulated past (e.g. 0.8 → keep 80% of the old estimate, add 20% of the new reading). Larger β = longer memory, smoother but laggier.

Unrolling shows why it is "exponentially weighted": EMAt = (1−β)[xt + βxt−1 + β²xt−2 + …] — each older reading's weight decays by a factor of β, so recent readings dominate and ancient ones fade smoothly (unlike a fixed-window moving average, which forgets abruptly).

Worked example (ice-cream sales, β = 0.8)

3.Momentum

Apply the EWMA to the gradients themselves. Keep a running "velocity" mt:

mt = β·mt−1 + (1−β)·gt  ;  wnew = wold − η·mt β ≈ 0.9 is typical. mt is the gradient history, not just the current gradient — so the step is "previous-gradient-aware."

Why it helps: along a consistent direction, successive gradients point the same way and add up, building speed; across an oscillating direction, gradients alternate sign and cancel in the average. The optimizer glides down the valley instead of rattling between its walls. (PyTorch implements this as SGD(..., momentum=0.9).)

4.RMSProp

Momentum fixes direction, but a single η still can't fit every parameter — some parameters routinely have large gradients, others tiny ones. RMSProp (Root Mean Square Propagation) tracks an EWMA of squared gradients and divides the step by its root:

St = ρ·St−1 + (1−ρ)·gt²  ;  wnew = wold − (η / √(St + ε))·gt Squaring removes the sign and keeps magnitude. ε (e.g. 1e-8) avoids division by zero.

The effect is a per-parameter adaptive learning rate: a parameter with large recent gradients gets a large St, so η is divided by a big number and the step shrinks (damping the wild direction); a parameter with small gradients gets a small St, so its step grows. The learning rate "no longer has to be fixed."

5.Adam

Adam (Adaptive Moment Estimation) combines the two memories — Momentum's EWMA of gradients (first moment, mt) and RMSProp's EWMA of squared gradients (second moment, vt):

mt = β₁mt−1 + (1−β₁)gt  ;  vt = β₂vt−1 + (1−β₂)gt²
wnew = wold − (η / √(vt + ε))·mt Momentum supplies the numerator (smoothed direction); RMSProp supplies the denominator (per-parameter scale). ε is the small anti-÷0 nudge.

Adam gets a smoothed direction and an adaptive step at once — which is why it converges quickly, stays stable, and is relatively forgiving of the initial η. AdamW is a common variant that decouples weight decay from the gradient update for better regularisation.

6.Hyperparameters & Bias Correction

SymbolMeaningTypical
η (lr)Base learning rate (step size)0.001 for Adam
β₁Decay for the gradient EWMA (momentum)0.9
β₂Decay for the squared-gradient EWMA0.999
εSmall constant to avoid dividing by zero1e-8
Bias correction: because m and v start at 0, the early estimates are biased toward 0. Adam divides by (1 − βt) — m̂t = mt/(1−β₁t), v̂t = vt/(1−β₂t) — so the first few steps aren't artificially tiny. PyTorch handles this internally.

8.Application: MNIST Classification

MNIST is 28×28 greyscale images of digits 0–9. The network flattens each image to 784 inputs → 128 hidden (ReLU) → 10 outputs:

784 → 128 → 10,   loss = CrossEntropy CrossEntropyLoss combines a softmax over the 10 outputs with the negative-log-likelihood — the right loss for multiclass classification (contrast MSE for regression).

DataLoader with batch_size=128 → 60,000 / 128 ≈ 469 mini-batch updates per epoch. Accuracy is measured by argmax(dim=1) over the 10 logits. The notebook trains the same architecture under SGD, Momentum, RMSprop, Adam, and AdamW to compare convergence, and can swap the hidden activation (ReLU / Tanh / Sigmoid / LeakyReLU / ELU / GELU) from Class 33.

9.In PyTorch

import torch
from torch import nn

opt = torch.optim.SGD(params, lr=0.01)                    # plain SGD / mini-batch
opt = torch.optim.SGD(params, lr=0.01, momentum=0.9)      # + momentum
opt = torch.optim.RMSprop(params, lr=0.001, alpha=0.99)   # alpha = ρ
opt = torch.optim.Adam(params, lr=0.001,
                       betas=(0.9, 0.999), eps=1e-8)       # β1, β2, ε
opt = torch.optim.AdamW(params, lr=0.001, weight_decay=1e-2)

# the loop is identical regardless of optimizer:
pred = model(x); loss = loss_fn(pred, y)
opt.zero_grad(); loss.backward(); opt.step()

10.Summary

The whole idea, in one paragraph

Plain gradient descent steps on one noisy gradient at a time, so it zig-zags. The exponentially weighted moving average (EWMA) smooths a noisy series by keeping a decaying memory of the past — EMA = β·prev + (1−β)·current. Apply it to the gradient and you get Momentum (mt), which captures a consistent direction; apply it to the squared gradient and you get RMSProp (St), which gives each parameter an adaptive step η/√(St+ε); combine both and you get Adam, w ← w − (η/√(vt+ε))·mt — the fast, stable default. We put it to work classifying MNIST digits with a 784→128→10 network and CrossEntropyLoss, with AWS EC2 deployment next.
