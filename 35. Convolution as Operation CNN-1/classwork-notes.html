Convolution as an Operation — CNNs, Part 1

Plain neural networks worked for MNIST, but they flatten an image and throw away its spatial structure. Today we define that problem precisely, then build the fix: the convolution operation — a small learnable filter that slides across the image to extract lines, edges and contours. That is the core of the Convolutional Neural Network.

Part 0: Revision — Where We Are

Traditional ML used data to understand patterns — we engineered the features ourselves. Deep learning is made of layers that understand all the different representations of the input data: inputs → hidden layers → weights, biases, activation functions → ŷ, trained with backpropagation and optimizers (SGD, Momentum, RMSProp, Adam). The road ahead: CNNs → overfitting & handling overfitting in NNs → Natural Language Processing → RNNs → Attention & Transformers → Generative AI (where deep learning ends and Gen AI begins).

Part I: What Does a Neural Network Actually Understand?

A dense network takes a global weighted sum of its inputs — it looks at global patterns. To feed an image in, we must first flatten it:

28 × 28 image → flatten → 784 pixel values (784 × 1 vector) Rows of the image are laid end-to-end into one long column. The network sees a list of numbers.

The problem — spatial information is lost. In the image, pixel 1 is close to pixel 6; pixels 1, 2, 6, 7 are neighbours. That local arrangement — the structure — is what defines a number. But once flattened, neighbouring pixels can end up far apart in the vector, and a global weighted sum can total the right brightness while missing the local pattern / alignment completely.

Problem definition — what is spatial info? It is where pixels are located and how neighbouring pixels relate to each other. A dense network has no local connectivity, so it cannot see that nearby pixels form a stroke.

Part II: A Search for a Spatial-Information-Preserving Network

Neural networks did work well for MNIST — but only because MNIST as an image is simple (small, centred, clean). Real images are not. So what makes up an image?

  • Lines, edges and contours.
  • Focus on functions that extract lines, edges and contours from an image.
  • Make those functions learnable — let the NN learn and extract the useful info on lines, edges and contours for proper classification.

That spatial-preserving network is the Convolutional Neural Network (CNN), and its core operation is convolution.

Part III: The Convolution Operation

Definition. Convolution is an operation where a small filter (kernel) moves across an image and produces a response at every position. At each stop, multiply the overlapping image patch element-wise by the kernel, then sum — one number per position. The grid of responses is the feature map.

response(at a position) = Σ (image patch × kernel) Slide the kernel one step at a time across the whole image; collect every response into the feature map. Kernels are often 2×2 or 3×3.

Worked example — a vertical-edge kernel

Take a patch that is bright on the left (value 10) and dark on the right (value 0), and the kernel [1,0,-1] on each of its 3 rows:

Patch typeEach row: 1·L + 0·M + (−1)·RΣ over 3 rows
Flat (all 10)10 − 10 = 00
Edge (10 | 0)10 − 0 = +10+30

A patch inside a flat region cancels to 0; a patch straddling the edge lights up (+30). The kernel responds only where brightness changes — i.e. "where is the edge?" A top-to-bottom gradient kernel reads from −1 (white) to +1 (black); left-to-right kernels catch vertical edges.

Example kernels (from the notebook)

# horizontal-edge (top vs bottom)
[[-1,-1,-1],
 [ 0, 0, 0],
 [ 1, 1, 1]]

# vertical-edge (left vs right)
[[-1, 0, 1],
 [-1, 0, 1],
 [-1, 0, 1]]

In code, convolution is scipy.signal.correlate2d(image, kernel, mode='same'), and we keep only the positive response with np.maximum(output, 0) (a ReLU) to visualise the detected edges.

Output size

output = (input − kernel + 1) per side A 3×3 kernel on 28×28 → 26×26. A 5×5 kernel on 28×28 → 24×24. A 2×2 kernel on 5×5 → 4×4. The map shrinks by (kernel − 1).

Part IV: CNNs — Multiple Filters & Stacked Layers

What if I have multiple filters? One kernel detects one kind of edge; use n filters / kernels and you get n feature maps stacked into a volume:

28×28 image —(n filters, 5×5)→ 24 × 24 × n Depth n = how many different patterns we look for. The values of these filters are learnable — gradient descent + backpropagation tune them (they are the "n" weights of this layer).

What if I stack layers of filters? Early layers learn simple lines & edges; deeper layers combine them into corners, curves and contours, then object parts, then whole objects — enough to tell cat from dog from car. Because early layers learn generic edges, trained CNNs can be reused — transfer learning: keep the edge/contour layers, retrain only the top.

From feature maps to a prediction. After the convolutional layers, the final volume (e.g. 4×4×100 = 1600) is flattened and sent to a normal dense head → 128 → … → k class scores, trained end-to-end with backpropagation.

import torch.nn as nn
model = nn.Sequential(
    nn.Conv2d(1, 32, kernel_size=3), nn.ReLU(),   # 32 learnable filters
    nn.Conv2d(32, 64, kernel_size=3), nn.ReLU(),
    nn.Flatten(),
    nn.Linear(64*24*24, 128), nn.ReLU(),
    nn.Linear(128, 10)                            # k classes
)
