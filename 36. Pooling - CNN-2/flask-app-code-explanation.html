1.Project Structure

CatsVsDogs/ ├── app.py # the Flask web server ├── model.py # the CNN class (must match the notebook) ├── cat_dog_model.pth # trained weights saved from the notebook ├── requirements.txt # Python dependencies ├── templates/ │ └── index.html # the upload + result page (Jinja2) └── static/ └── style.css # page styling

This is the standard Flask layout: Python at the root, HTML in templates/ (rendered server-side with Jinja2), and CSS/JS/images in static/. The .pth is the bridge from the notebook — it carries the learned weights.

2.model.py — the Architecture

model.py 
import torch.nn as nn

class CatDogCNN(nn.Module):
  def __init__(self):
    super().__init__()
    self.network = nn.Sequential(
        nn.Conv2d(3,  16, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(16, 32, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.Conv2d(32, 64, kernel_size=3, padding=1), nn.ReLU(), nn.MaxPool2d(2),
        nn.AdaptiveAvgPool2d((4, 4)), nn.Flatten(),
        nn.Linear(64*4*4, 32), nn.ReLU(),
        nn.Linear(32, 2))

  def forward(self, x):
    return self.network(x)
This must be byte-for-byte the same architecture as the notebook. A state_dict is just a dictionary of tensors keyed by layer name/shape — it carries no structure. load_state_dict only works if the model you build here has the exact same layers, in the same order, with the same shapes. If they differ, loading throws a size-mismatch error. (See the notebook explanation for the per-layer shapes.)

3.app.py — Imports & Config

app.py 
import base64
from io import BytesIO
from pathlib import Path
import torch
from flask import Flask, render_template, request, jsonify
from PIL import Image, UnidentifiedImageError
from torchvision import transforms
from model import CatDogCNN

MODEL_PATH = Path(__file__).parent / "cat_dog_model.pth"
LABELS = ["Cat", "Dog"]

app = Flask(__name__)
app.config['MAX_CONTENT_LENGTH'] = 5 * 1024 * 1024  # reject uploads > 5 MB
  • base64 / BytesIO — used later to embed the uploaded image back into the page as a preview without saving a file to disk.
  • Path(__file__).parent / "cat_dog_model.pth" — builds the model path relative to this file, so the app works no matter the working directory (important on EC2).
  • LABELS = ["Cat", "Dog"] — index 0 → Cat, index 1 → Dog. This order must match the notebook's class_to_idx ({cats:0, dogs:1}).
  • MAX_CONTENT_LENGTH — Flask rejects any request body larger than 5 MB before it reaches your code — a basic safety limit.

4.Loading the Model Once (at Startup)

app.py 
if not MODEL_PATH.exists():
    raise FileNotFoundError(f"Model file not found at {MODEL_PATH}...")

model = CatDogCNN()
model.load_state_dict(torch.load(MODEL_PATH, map_location=torch.device('cpu')))
model.eval()
  • Fail fast — if the weights file is missing, the app refuses to start with a clear message (better than a confusing error on the first request).
  • Loaded once at import time, not per request — loading a model is expensive, so you do it a single time when the server boots and reuse it for every upload.
  • map_location='cpu' — the model was likely trained on a GPU; this remaps the weights onto the CPU so it runs on a cheap, GPU-less EC2 instance.
  • model.eval() — switches to inference mode (disables training-only behaviour). Essential before predicting.

5.The Preprocessing Pipeline

app.py 
preprocess = transforms.Compose([
    transforms.Resize((128, 128)),
    transforms.ToTensor(),
])
Must mirror the validation transform from the notebook — resize to 128×128 and convert to a tensor, with no random flip. The model only understands inputs shaped exactly like the ones it trained on. If training had normalised the pixels, you would have to repeat that here too.

6.The Route — GET vs POST

app.py 
@app.route('/', methods=['GET', 'POST'])
def home():
    prediction = score = preview = error = None
    if request.method == 'POST':
        uploaded = request.files.get('image')
        ...
    return render_template('index.html', prediction=prediction,
                           score=score, preview=preview, error=error)

One route handles both verbs:

  • GET (first visit) — all values are None, so the template just shows the empty upload form.
  • POST (form submitted) — read the uploaded file, run the model, and pass the results back into the same template.

7.Validation & the Prediction

app.py 
if not uploaded:
    return jsonify({"error": "No file uploaded"}), 400
elif Path(uploaded.filename).suffix.lower() not in ['.jpg', '.jpeg', '.png']:
    return jsonify({"error": "Invalid file type..."}), 400
else:
    try:
        with Image.open(uploaded.stream) as original:
            if original.width * original.height > 5 * 1024 * 1024:
                return jsonify({"error": "Image size exceeds 5MB limit."}), 400
            image = original.convert('RGB')
            x = preprocess(image).unsqueeze(0)          # add batch dim: [1,3,128,128]
            with torch.inference_mode():
                probabilities = torch.softmax(model(x), dim=1)[0]
                class_index = int(probabilities.argmax().item())
                prediction  = LABELS[class_index]
                score = round(float(probabilities[class_index]) * 100, 1)
                buffer = BytesIO(); image.save(buffer, format="JPEG")
                preview = base64.b64encode(buffer.getvalue()).decode('ascii')
    except (UnidentifiedImageError, OSError, ValueError):
        error = "Invalid image file..."

Defence first, then inference:

  • Three guards — no file → 400; wrong extension → 400; wrong/corrupt image bytes → caught by the try/except. Never trust a user upload.
  • .convert('RGB') — forces 3 channels (handles greyscale or RGBA inputs), matching the model's 3-channel input.
  • .unsqueeze(0) — the model expects a batch: shape [batch, channels, H, W]. One image becomes a batch of one → [1, 3, 128, 128].
  • torch.inference_mode() — like no_grad() but even faster; no gradients are tracked during prediction.
  • torch.softmax(logits, dim=1) — turns the 2 raw logits into probabilities that sum to 1. (Training used CrossEntropyLoss which applies softmax internally, so the model itself outputs logits — we add softmax here to get a human-readable confidence.)
  • argmax → LABELS[...] — pick the higher-probability class and map 0/1 to "Cat"/"Dog"; score is that probability as a percentage.
  • The preview — the image is re-encoded to JPEG in memory and base64-encoded, so the template can show it inline (data:image/jpeg;base64,...) without writing any file to the server's disk.
Honest limitation (stated on the page): the model only knows two labels, so it will output Cat or Dog even for a photo of neither. The score is a confidence, not a guarantee.

8.The Template — templates/index.html

templates/index.html 
<form method="POST" enctype="multipart/form-data">
  <input type="file" name="image" accept="image/jpeg,image/png,..." required>
  <button type="submit">Predict</button>
</form>

{% if error %}  <p class="error">{{ error }}</p>  {% endif %}
{% if preview %}<img src="data:image/jpeg;base64,{{ preview }}">{% endif %}
{% if prediction %}
  <h2>{{ '🐱' if prediction == 'Cat' else '🐶' }} {{ prediction }}</h2>
  <p>Model score: <strong>{{ score }}%</strong></p>
{% endif %}
  • enctype="multipart/form-data" — required for file uploads; without it the image bytes aren't sent.
  • name="image" — matches request.files.get('image') in app.py.
  • Jinja2 {% if %} blocks — the same page shows nothing, an error, or the prediction + preview, depending on which variables the route passed back. Server-side rendering: no JavaScript needed.

9.requirements.txt

requirements.txt 
Flask>=3.1,<4
Pillow>=11,<13
torch>=2.6,<3
torchvision>=0.21,<1
gunicorn>=22,<26; platform_system != "Windows"
  • Pinned ranges (>=x,<y) keep the install reproducible while allowing patch updates.
  • Pillow is the imaging library behind PIL (opening/converting the upload).
  • gunicorn — a production WSGI server for Linux/macOS (the platform_system != "Windows" marker skips it on Windows dev machines). Flask's built-in server is for development only; on EC2 you run the app under gunicorn.

10.Run It Locally, Then EC2

# local development
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python app.py                 # serves http://127.0.0.1:5000 (debug=True)

# production (EC2 / Linux) — gunicorn, no debug
gunicorn --bind 0.0.0.0:8000 app:app
Dev vs production. app.run(..., debug=True) at the bottom of app.py is for local use only — never run with debug=True on a public server (it exposes an interactive debugger). On EC2 you serve with gunicorn bound to 0.0.0.0 and open the port in the security group. The full step-by-step is in the GitHub → EC2 deployment guide.
Don't commit the virtual environment. .venv/ can be 800 MB+. It's already in .gitignore — the EC2 host builds its own with pip install -r requirements.txt. Only the code and the small cat_dog_model.pth get pushed.

In one paragraph

The Flask app rebuilds the exact CNN architecture in model.py, loads the notebook's saved weights once at startup (remapped to CPU, in eval mode), and exposes one route. On GET it shows an upload form; on POST it validates the file, preprocesses the image identically to validation (resize 128×128 → tensor → batch dim), runs it through the model under inference_mode, softmaxes the two logits into a Cat/Dog probability, and re-renders the page with the label, score and an inline preview. Pinned dependencies and gunicorn make it ready to clone and serve on an AWS EC2 instance.
