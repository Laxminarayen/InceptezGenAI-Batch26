Cells 6–7.Transforms — Train vs Validation

preprocessing 
train_transform = transforms.Compose([
    transforms.Resize((128, 128)),
    transforms.RandomHorizontalFlip(),   # data augmentation
    transforms.ToTensor(),
])
val_transform = transforms.Compose([
    transforms.Resize((128, 128)),
    transforms.ToTensor(),
])
  • Resize((128,128)) — every image becomes 128×128 so the network sees a fixed input size.
  • RandomHorizontalFlip() — randomly mirrors training images left↔right. This is data augmentation: it multiplies the effective dataset and fights overfitting. A flipped cat is still a cat.
  • ToTensor() — converts the PIL image (H×W×C, values 0–255) into a PyTorch tensor (C×H×W, values 0.0–1.0).
Why no flip on validation? Augmentation is a training trick. For validation we want a stable, deterministic measure of accuracy, so we only resize and convert — no randomness.

Cells 8–9.ImageFolder Datasets

data 
train_data = datasets.ImageFolder(DATA_DIR / "train", transform=train_transform)
val_data   = datasets.ImageFolder(DATA_DIR / "validation", transform=val_transform)

ImageFolder reads a directory where each sub-folder is a class. It automatically assigns integer labels alphabetically (cats → 0, dogs → 1) and applies the given transform when an image is loaded. Each item is a (image_tensor, label) pair.

Cells 10–11.DataLoaders

batching 
train_loader = DataLoader(train_data, batch_size=32, shuffle=True)
val_loader   = DataLoader(val_data,   batch_size=32, shuffle=False)
  • batch_size=32 — the network processes 32 images per step (mini-batch gradient descent, from Class 34).
  • shuffle=True for training — reshuffles every epoch so the model doesn't learn the order of the data.
  • shuffle=False for validation — order doesn't matter when only measuring accuracy, and keeping it fixed makes runs reproducible.

Cell 16.The CNN Model

model 
class CatDogCNN(nn.Module):
  def __init__(self):
    super().__init__()
    self.network = nn.Sequential(
        nn.Conv2d(in_channels=3,  out_channels=16, kernel_size=3, padding=1),
        nn.ReLU(),
        nn.MaxPool2d(kernel_size=2),                 # 128 → 64

        nn.Conv2d(in_channels=16, out_channels=32, kernel_size=3, padding=1),
        nn.ReLU(),
        nn.MaxPool2d(kernel_size=2),                 # 64 → 32

        nn.Conv2d(in_channels=32, out_channels=64, kernel_size=3, padding=1),
        nn.ReLU(),
        nn.MaxPool2d(kernel_size=2),                 # 32 → 16

        nn.AdaptiveAvgPool2d((4, 4)),              # 16 → 4 (fixed size)
        nn.Flatten(),
        nn.Linear(in_features=64*4*4, out_features=32),
        nn.ReLU(),
        nn.Linear(in_features=32, out_features=2))   # Cat / Dog

  def forward(self, x):
    return self.network(x)

device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model = CatDogCNN().to(device)

This is the heart of the class — the Conv → ReLU → MaxPool pattern from the lecture, repeated three times with a growing number of filters (16 → 32 → 64), then a dense head.

LayerWhat it doesOutput shape (per image)
inputRGB image3 × 128 × 128
Conv2d(3,16,3,padding=1) + ReLU16 learnable 3×3 filters; padding=1 keeps the size16 × 128 × 128
MaxPool2d(2)2×2 max pooling, halves H & W16 × 64 × 64
Conv2d(16,32,3,p=1) + ReLU + Pool32 filters, then halve32 × 32 × 32
Conv2d(32,64,3,p=1) + ReLU + Pool64 filters, then halve64 × 16 × 16
AdaptiveAvgPool2d((4,4))Average-pools to a fixed 4×4 no matter the input64 × 4 × 4
Flatten()Unroll to a vector64·4·4 = 1024
Linear(1024,32) + ReLUDense hidden layer32
Linear(32,2)Two class scores (logits)2
  • padding=1 on a 3×3 conv keeps the spatial size the same, so only the pooling layers shrink it — making the arithmetic easy to follow.
  • AdaptiveAvgPool2d((4,4)) forces a fixed 4×4 output. This guarantees the flattened size is always 64·4·4 = 1024, so the Linear layer's input never breaks even if the input image size changes.
  • nn.Sequential chains the layers; forward just runs the input through them.
  • .to(device) moves the model to the GPU (cuda) if available, else CPU.
  • The output layer has 2 units (not 1) — two class logits used with CrossEntropyLoss.

Cell 18.Loss & Optimizer

training setup 
loss_function = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
  • CrossEntropyLoss — the right loss for classification. In PyTorch it applies softmax internally, so the model outputs raw logits (no softmax layer in the model).
  • Adam(lr=0.001) — the adaptive optimizer from Class 34 (Momentum + RMSProp combined). model.parameters() hands it every learnable weight to update.

Cell 19.The Training Loop

training 
best_accuracy = -1.0
train_loss = []
val_accuracies = []
Model_file = Path("cat_dog_model.pth")
epochs = 100

for epoch in range(epochs):
  model.train()                                  # train mode
  total_loss = 0.0
  for images, labels in train_loader:
    images, labels = images.to(device), labels.to(device)
    optimizer.zero_grad()                        # clear old gradients
    outputs = model(images)                      # forward pass
    loss = loss_function(outputs, labels)
    loss.backward()                              # backpropagation
    optimizer.step()                             # update weights
    total_loss += loss.item()
  average_loss = total_loss / len(train_loader)
  train_loss.append(average_loss)

  model.eval()                                   # evaluation mode
  correct = 0
  with torch.no_grad():                           # no gradients when scoring
    for images, labels in val_loader:
      images = images.to(device)
      outputs = model(images)
      predictions = outputs.argmax(dim=1).cpu()
      correct += (predictions == labels).sum().item()
  accuracy = correct / len(val_loader.dataset)
  val_accuracies.append(accuracy)

  if accuracy > best_accuracy:                     # keep the best model only
    best_accuracy = accuracy
    torch.save(model.state_dict(), Model_file)

The classic PyTorch loop, with validation and checkpointing:

  • model.train() / model.eval() — switch modes. They matter when the model has dropout or batch-norm (train vs inference behaviour). Good habit even here.
  • The 5-step update — zero_grad → forward → loss → backward → step. zero_grad() is essential: PyTorch accumulates gradients, so you must clear them each batch.
  • torch.no_grad() — during validation we don't need gradients; this saves memory and speeds things up.
  • outputs.argmax(dim=1) — the predicted class is the index of the larger of the 2 logits (0 = cat, 1 = dog).
  • accuracy = correct / len(val_loader.dataset) — fraction of validation images classified correctly.
  • torch.save(model.state_dict(), ...) — saves only the weights (not the code) whenever validation accuracy improves. This cat_dog_model.pth file is what the Flask app loads. Saving on the best epoch is a simple form of early-stopping / best-checkpoint.

Appendix.Common Gotchas

  • Colab paths — !unzip and /content/… are Colab-only; adapt for a local run.
  • Last cell typo — the final print(f"... {Model_File} ...") uses Model_File but the variable is Model_file (Python is case-sensitive). Fix the capitalisation or that print will raise NameError. The model is still saved correctly above it.
  • Validation labels & device — labels stay on CPU while predictions are moved with .cpu(), so the comparison lines up. If you move labels to the GPU, compare on the same device.
  • Label order must match the app — class_to_idx is {cats:0, dogs:1}, so the Flask app's LABELS = ["Cat", "Dog"] must be in that exact order.

In one paragraph

The notebook downloads a cats-vs-dogs set, resizes images to 128×128 (with a random flip for training-time augmentation), wraps them in ImageFolder datasets and batched DataLoaders, defines a three-block Conv→ReLU→MaxPool CNN ending in a small dense head (1024 → 32 → 2), and trains it with Adam + CrossEntropyLoss for 100 epochs — saving the weights (cat_dog_model.pth) whenever validation accuracy hits a new best. That saved file is exactly what the Flask app serves.
