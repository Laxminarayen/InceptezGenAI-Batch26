# Image classifier for t2.micro / t3.micro EC2

A simple **custom image classifier** with:
- Jupyter notebook training (PyTorch + pre-trained MobileNetV3-Small)
- ONNX model export
- Very small Flask + ONNX Runtime CPU inference server (no PyTorch required on EC2)
- Browser upload form, JSON prediction endpoint, and health check

**Why ONNX?** AWS t2.micro/t3.micro instances have 1 GiB of RAM. Train somewhere
else (Google Colab, workstation, laptop); copy only the exported `artifacts/`
files to the EC2 server.

## Folder structure

```text
image-classifier-ec2/
├── train.ipynb
├── app.py
├── requirements.txt            # EC2/runtime only
├── requirements-train.txt      # notebook/training machine only
├── image-classifier.service    # optional systemd service for Ubuntu
├── data/
│   ├── README.md
│   ├── train/<class_name>/*.jpg
│   └── val/<class_name>/*.jpg
└── artifacts/                  # generated by notebook
    ├── model.onnx
    └── classes.json
```

## 1. Prepare labeled image data

See `data/README.md`. Example with two classes:

```text
data/train/cats/1.jpg
data/train/cats/2.jpg
data/train/dogs/1.jpg
data/train/dogs/2.jpg
data/val/cats/1.jpg
data/val/dogs/1.jpg
```

Use the same class names in training and validation and enough examples per class.

## 2. Train locally or in Google Colab

Use **Python 3.10–3.12**, ideally on a computer or Colab with enough RAM.
From the project root, run:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-train.txt
jupyter notebook train.ipynb
```

On Windows, activate via `.venv\Scripts\activate`. In Colab, upload the notebook,
requirements, and your data to the same working directory (or mount Drive and
adjust `DATA_DIR` in the first code cell).

Run notebook cells top to bottom. After training it creates:

- `artifacts/model.onnx` – image classification network
- `artifacts/classes.json` – class label list

Notebook fine-tunes the final classifier layer of a pretrained MobileNetV3-Small.
Internet is needed once to download pretrained ImageNet weights (~10 MB).
Training accuracy depends on your images/data quality.

## 3. Run locally

To test inference in a **separate environment** (or in your notebook environment):

```bash
python -m pip install -r requirements.txt
python app.py
```

Open http://127.0.0.1:8000 . Try the JSON API:

```bash
curl -F "image=@test.jpg" http://127.0.0.1:8000/api/predict
curl http://127.0.0.1:8000/health
```

## 4. Deploy to AWS EC2 (Ubuntu 24.04, x86_64)

1. Launch a **t3.micro** (or **t2.micro**) with Ubuntu 24.04 **x86_64** image.
   These have 1 GiB RAM. Allow inbound SSH (22) from your IP. For a short-lived
   demo, allow TCP **8000** from your IP only. Do not expose an unprotected
   demo port to the whole internet.
2. After training, copy **app.py**, **requirements.txt**, and the entire
   **artifacts/** directory to EC2 (or copy the whole project minus training data).
   For example, from the parent directory on your local computer:

```bash
scp -i your-key.pem -r image-classifier-ec2 ubuntu@EC2_PUBLIC_IP:/home/ubuntu/
```

3. SSH to EC2 and install the lightweight inference dependencies:

```bash
ssh -i your-key.pem ubuntu@EC2_PUBLIC_IP
sudo apt update
sudo apt install -y python3-venv
cd ~/image-classifier-ec2
python3 -m venv .venv
source .venv/bin/activate
pip install --no-cache-dir -r requirements.txt

# Low-memory configuration: just ONE worker and ONE thread.
gunicorn --workers 1 --threads 1 --bind 0.0.0.0:8000 --timeout 120 app:app
```

4. Open `http://EC2_PUBLIC_IP:8000` from the IP allowed in your EC2 security group.

For a persistent server that restarts after reboot, use the included **optional**
`image-classifier.service` file (assumes username `ubuntu` and the paths above):

```bash
sudo cp image-classifier.service /etc/systemd/system/image-classifier.service
sudo systemctl daemon-reload
sudo systemctl enable --now image-classifier
sudo systemctl status image-classifier
```

To see app logs: `sudo journalctl -u image-classifier -f`.

For a public-facing production service, put Nginx and HTTPS in front of Gunicorn,
limit upload rates, and restrict port 8000 to localhost. The provided direct-port
setup is for a simple controlled demo.

## Constraints / troubleshooting

- **Never run training on the micro instance**: its memory and burstable CPU are too small.
- On EC2 install only `requirements.txt` (not `requirements-train.txt`).
- If the app says `Missing artifacts`, train first and upload both output files.
- ONNX Runtime needs a compatible x86_64 CPU Linux image; use Ubuntu x86_64,
  not an ARM-based instance unless you confirm wheel compatibility.
- With only 1 GiB RAM, keep Gunicorn at one worker and avoid large concurrent uploads.
- Pretrained MobileNetV3-Small is compact but predictions can still be inaccurate
  with too little training data, out-of-distribution images, or visually similar classes.
- If pip runs out of memory, enable a small swapfile or install dependencies on a larger
  instance first. A t3.small is more comfortable for significant traffic.
