Cells 0–2.Context: Keep the Model Light

markdown

The notebook opens by framing computer vision (classification, localization, segmentation, generation) and a key deployment constraint: keep the model light. A lightweight model means (1) lower parameter count, (2) smaller storage, (3) fewer environment dependencies — which is exactly why we pick MobileNet and export to ONNX, and why Dockerization is mentioned as a way to ship the whole thing reproducibly.

Cell 7.Setup & Hyperparameters

code · imports + config 
from pathlib import Path
import copy, json, random
import numpy as np
import torch
from torch import nn
from torch.utils.data import DataLoader, Subset
from torchvision import datasets, models, transforms

SEED = 42
random.seed(SEED); np.random.seed(SEED); torch.manual_seed(SEED)

DATA_DIR = Path("data"); EXPORT_DIR = Path("artifacts")
DATA_DIR.mkdir(parents=True, exist_ok=True)
EXPORT_DIR.mkdir(parents=True, exist_ok=True)

IMAGE_SIZE   = 128
BATCH_SIZE   = 64 if torch.cuda.is_available() else 32
EPOCHS       = 5
LEARNING_RATE= 1e-3
VAL_FRACTION = 0.10
DEVICE = torch.device("cuda" if torch.cuda.is_available() else "cpu")
  • Imports — models is the new one: torchvision.models holds the pre-trained networks (MobileNet, ResNet…). Subset lets us pick specific indices for the train/val split.
  • SEED = 42 + the three seed() calls — seed Python's random, NumPy, and PyTorch so shuffles and weight init are reproducible: the same split and results every run.
  • EXPORT_DIR = "artifacts" — where the ONNX model and labels will be written (the Flask app reads from here).
  • IMAGE_SIZE = 128 — CIFAR-10 images are natively 32×32; we upscale to 128×128 to suit the pre-trained backbone (and match the Flask app's resize).
  • BATCH_SIZE — 64 on GPU, 32 on CPU (smaller batches fit less memory).
  • EPOCHS = 5 — only 5 passes, because transfer learning converges fast (vs the old "1000 epochs for 3 days").
  • DEVICE — use the GPU if present, else CPU.

    transforms.ToTensor(),
    transforms.Normalize(mean, std)])
eval_tf = transforms.Compose([

    transforms.ToTensor(),
    transforms.Normalize(mean, std)])       # no flip for val/test

train_source = datasets.ImageFolder(str(train_dir), transform=train_tf)
val_source   = datasets.ImageFolder(str(train_dir), transform=eval_tf)

  • mean / std — the ImageNet normalization constants. Because the backbone was pre-trained on ImageNet, we must feed it images normalized the same way. (The Flask app repeats these exact numbers.)

  • Normalize(mean, std) — subtract the mean, divide by std per channel, after ToTensor().
  • Two views of the same train folder — train_source (with flips) and val_source (no flips) point at the same directory but with different transforms; the split below selects disjoint indices from each.

Cell 12.Reproducible Stratified Validation Split

code · train/val split 
train_indices, val_indices = [], []
for class_id in range(len(class_names)):
    indices = [i for i, target in enumerate(train_source.targets)
               if target == class_id]
    random.Random(SEED + class_id).shuffle(indices)
    n_val = int(len(indices) * VAL_FRACTION)
    val_indices.extend(indices[:n_val])
    train_indices.extend(indices[n_val:])

train_ds = Subset(train_source, train_indices)
val_ds   = Subset(val_source,   val_indices)
train_dl = DataLoader(train_ds, batch_size=BATCH_SIZE, shuffle=True, ...)
val_dl   = DataLoader(val_ds,   batch_size=BATCH_SIZE, shuffle=False, ...)
test_dl  = DataLoader(test_ds,  batch_size=BATCH_SIZE, shuffle=False, ...)

assert len(train_ds) == 45_000 and len(val_ds) == 5_000
  • Stratified = the split keeps each class's proportion. We loop per class and take 10% (VAL_FRACTION) of that class's images for validation — so validation has exactly 500 of each of the 10 classes, not a random mix that might under-represent some class.
  • random.Random(SEED + class_id).shuffle(...) — a dedicated, seeded RNG per class → the split is reproducible and independent across classes.
  • Subset(..., indices) — builds the train/val datasets from the chosen indices; val_ds draws from val_source (no flips).
  • DataLoaders — batch the data; shuffle only the training loader. Result: 45,000 train / 5,000 val / 10,000 test, confirmed by the assert.

Cell 14.Load & Freeze MobileNetV3-Small

code · the transfer-learning core 
weights = models.MobileNet_V3_Small_Weights.DEFAULT
model = models.mobilenet_v3_small(weights=weights)

for p in model.parameters():
    p.requires_grad = False   # freeze the whole backbone

n_features = model.classifier[-1].in_features
model.classifier[-1] = nn.Linear(n_features, len(class_names))  # new 10-class head
model = model.to(DEVICE)

loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.classifier[-1].parameters(), lr=LEARNING_RATE)

This is the heart of the lesson — the four lines that make it transfer learning:

  • weights = ...DEFAULT → mobilenet_v3_small(weights=weights) — download MobileNetV3-Small with its ImageNet-pretrained weights (not random).
  • for p in model.parameters(): p.requires_grad = False — freeze every parameter. Frozen params get no gradients, so the backbone never changes — this is feature extraction. (The notebook's own comment: "where the finetuning is blocked — No retraining of weights".)
  • model.classifier[-1].in_features — read how many features feed the final layer, then replace that layer with a fresh Linear(n, 10). A newly created layer has requires_grad=True by default, so only the head is trainable.
  • AdamW(model.classifier[-1].parameters(), ...) — crucially, we hand the optimizer only the head's parameters, so it can't (and won't) touch the frozen backbone. AdamW = Adam with decoupled weight decay (a touch of L2 regularization).
  • The cell prints the trainable parameter count — it will be tiny (just the head) compared to the full network.

Cell 15.The Training Loop

code · train + validate + keep best 
best_val_acc, best_weights = -1.0, None

for epoch in range(EPOCHS):
    model.train()
    model.features.eval()   # keep frozen BatchNorm stats fixed
    for images, targets in train_dl:
        images, targets = images.to(DEVICE), targets.to(DEVICE)
        optimizer.zero_grad()
        logits = model(images)
        loss = loss_fn(logits, targets)
        loss.backward()
        optimizer.step()
        ...
    model.eval()
    with torch.inference_mode():
        for images, targets in val_dl:
            logits = model(images.to(DEVICE))
            val_correct += (logits.argmax(1) == targets.to(DEVICE)).sum().item()
    val_acc = val_correct / val_count

    if val_acc > best_val_acc:
        best_val_acc = val_acc
        best_weights = copy.deepcopy(model.state_dict())

model.load_state_dict(best_weights)   # restore the best epoch
  • model.train() then model.features.eval() — a subtle but important pair. We put the model in train mode (so the head trains), but immediately put the frozen feature extractor back in eval mode so its BatchNorm running statistics stay fixed. If we left BatchNorm in train mode it would keep updating its stats from our data even though the weights are frozen — hurting the pre-trained features.
  • The 5-step update — zero_grad → forward (logits) → loss → backward → step, the same loop as earlier classes. Only the head's gradients are non-zero.
  • torch.inference_mode() — fast, gradient-free validation.
  • logits.argmax(1) == targets — count correct predictions to compute validation accuracy.
  • Best-checkpoint via copy.deepcopy(model.state_dict()) — whenever validation accuracy improves, snapshot the weights in memory. After all epochs, load_state_dict(best_weights) restores the best one. This is a manual early-stopping / best-model-selection — we keep the generalizing model, not the last (possibly overfit) one.

Cell 19.Export to ONNX

code · the deployment artifact 
model = model.cpu().eval()
example = torch.randn(1, 3, IMAGE_SIZE, IMAGE_SIZE)   # dummy input, right shape

torch.onnx.export(
    model, example, str(onnx_path),
    input_names=["images"], output_names=["logits"],
    opset_version=17, dynamo=False)

with (EXPORT_DIR / "classes.json").open("w") as f:
    json.dump(class_names, f, indent=2)
  • model.cpu().eval() — export from CPU in eval mode so the traced graph matches inference.
  • example = torch.randn(1,3,128,128) — ONNX export traces the model by running one example through it, so it needs a tensor of the exact input shape (batch 1, 3 channels, 128×128). The values don't matter, only the shape.
  • torch.onnx.export(...) — writes model.onnx, a framework-neutral graph. input_names/output_names label the tensors ("images" → "logits"); opset_version=17 fixes the ONNX operator set for compatibility.
  • classes.json — saves the 10 label names in order, so the server can map output index → class name. The model file + this label file are the only two things the EC2 app needs — no PyTorch.

Cell 21.Verify ONNX Matches PyTorch

code · trust but verify 
import onnx, onnxruntime as ort
onnx.checker.check_model(onnx.load(str(onnx_path)))        # structural check
session = ort.InferenceSession(str(onnx_path), providers=["CPUExecutionProvider"])

torch_logits = model(example).numpy()
onnx_logits  = session.run(None, {session.get_inputs()[0].name: example.numpy()})[0]
np.testing.assert_allclose(onnx_logits, torch_logits, rtol=1e-3, atol=1e-3)
  • onnx.checker.check_model — validates the exported graph is well-formed.
  • Run the same example through both PyTorch and ONNX Runtime, then assert_allclose that the outputs match within a tiny tolerance. This proves the export didn't change the model's behaviour before you ship it — if this fails, don't deploy.
Where to run this. Train in Jupyter/Colab (GPU helps), not on the 1 GiB EC2 box. After export, copy only artifacts/model.onnx and artifacts/classes.json next to app.py on EC2.

In one paragraph

The notebook downloads labeled CIFAR-10, normalizes images to ImageNet statistics at 128×128, and builds a reproducible stratified 45k/5k/10k split. It loads ImageNet-pretrained MobileNetV3-Small, freezes the entire backbone, replaces the final layer with a fresh 10-class head, and trains only that head with AdamW for 5 epochs — keeping BatchNorm frozen and snapshotting the best-validation weights. After reporting held-out test accuracy, it exports the model to a framework-neutral ONNX file plus a classes.json, and verifies ONNX output matches PyTorch. Those two artifacts are all the Flask app needs on EC2.
