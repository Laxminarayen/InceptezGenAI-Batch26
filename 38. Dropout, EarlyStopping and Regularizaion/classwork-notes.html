Part 0: The Experiment — Forcing Overfitting on Purpose

We use sklearn's load_digits() — 1,797 small 8×8 handwritten digits, bundled with scikit-learn (no download, no 403). To make overfitting visible and exaggerated on a CPU, we rig the experiment:

  • Tiny training set — only 120 images (a "more data" run uses 800).
  • 25% corrupted training labels — a quarter of the training labels are deliberately changed to wrong digits.
  • Clean validation & test — those labels stay untouched, so they reveal the truth.
Train learns weights · Validation chooses settings/checkpoints · Test untouched until the end Overfitting = low training loss but rising validation loss. If a model hits 100% on intentionally-wrong labels, it is memorizing noise, not learning digits.

Part I: The Two Models — MLP & CNN

Both models can optionally use dropout, and both can be built "small" (fewer params) to show capacity effects.

  • MLP — Flatten the 8×8 to 64 inputs → Linear(64,256) → Linear(256,128) → Linear(128,10), ReLU between, optional Dropout(0.4).
  • CNN — two Conv2d+ReLU blocks with optional Dropout2d(0.2) and MaxPool2d, then a dense classifier with optional Dropout(0.4).
Both overfit. The MLP memorizes easily; the CNN's weight-sharing and spatial bias help, but do not prevent memorization on a small, noisy set. Watch training loss fall while validation loss rises.

Part II: The Training Function

One transparent fit() drives every experiment. Each batch is the four steps: forward → loss → backward() → optimizer.step(). After each epoch it records train/val loss and accuracy.

Dropout2d is not deleting filters. It randomly zeroes entire feature-map channels during training — it does not change the filter weights. Useful because neighbouring pixels in a channel are highly correlated, so dropping single activations leaks less information than dropping whole channels.
No fix is guaranteed. On tiny 8×8 digits, too much augmentation can erase helpful detail and hurt. Always interpret validation loss, not just training accuracy.

Part IV: Transfer Learning as a Fix

When the new task has little labeled data, reuse features from a related task. We pretrain a CNN on all 10 digits (800 images), freeze its feature extractor, attach a new Even-vs-Odd 2-class head, and train on just 80 examples — comparing against training the same model from scratch.

transfer_model = SimpleCNN(num_classes=2)
transfer_model.features.load_state_dict(pretrained.features.state_dict())  # reuse
for p in transfer_model.features.parameters():
    p.requires_grad = False          # freeze backbone; only the new head learns
Pretraining learns a useful representation; freezing keeps it fixed; the new head adapts. Transfer may or may not beat scratch — but with scarce, related data it often does.

Part V: One Honest Final Test

  1. Select the model with the lowest validation loss — never look at test during selection.
  2. Evaluate once on the untouched test set → the honest accuracy + a confusion matrix.
Golden rule: validation chooses, test confirms.Reusing the test set for tuning silently inflates your reported score.

Industry Checklist

  • Split correctly — keep related photos/patients/customers in the same split (avoid leakage).
  • Fit preprocessing statistics on the training split only.
  • Read train and validation curves together.
  • Prefer more representative data and correct bad labels; augment (label-preserving) train only.
  • Test dropout, weight decay, early stopping, and a simpler architecture.
  • Use a pretrained backbone when data is scarce and tasks are related.
  • Select on validation; evaluate once on the untouched test set; monitor after deployment.
Overfitting = excellent fit to training-specific details, weaker generalization.
Solutions = better data + sensible capacity + regularization + correct evaluation.
