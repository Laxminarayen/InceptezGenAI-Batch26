Part I · What Is Overfitting?

Great on training, weak on unseen

Overfitting = an excellent fit to training-specific details, but weaker generalization. The model learns the quirks (and even the mistakes) of the training set instead of the real pattern.

low training loss ≠ good real-world performanceThe validation curve — not the training curve — tells you when generalization starts to deteriorate.
Train / Validation / Test
Train learns the weights. Validation chooses settings & checkpoints (never updates weights). Test stays untouched until the one final evaluation.
We use sklearn's 8×8 digits (1,797 images, no download) — small on purpose, so overfitting is easy to see on a CPU.
The Setup · Forcing Overfitting on Purpose

A tiny set with 25% wrong labels

🔢

Small training set

Only 120 images (vs 800 for the "more data" run). Little data → easy to memorize.

🏷️

25% corrupted labels

A quarter of the training labels are deliberately flipped to wrong digits.

🧼

Clean val & test

Validation and test labels stay untouched — so they reveal the truth.

🚩 If a model reaches 100% accuracy against intentionally wrong training labels, it is memorizing noise — not learning digits. More training won't fix that.
Part II · Watch It Happen

Training loss falls, validation loss rises

Both an MLP (flatten 8×8 → dense) and a CNN (conv filters + pooling) overfit this noisy set. Convolutional weight-sharing helps, but it does not prevent memorization on small, noisy data.

The telltale sign: train accuracy climbs toward 100% while the generalization gap (train − validation) widens.
model.train() vs model.eval()
train() activates dropout during learning; eval() disables it for a fair, deterministic measurement. Forgetting eval() is a classic bug.
Every batch is the same 4 steps: forward → loss → backward() → optimizer.step().

The Toolbox · One Fix at a Time

Seven ways to regularize

🎲

Dropout

Temporarily hide random activations during training. Dropout2d hides whole CNN channels.

⚖️

Weight decay (L2)

Discourage overly large weights — AdamW(..., weight_decay=0.1).

⏹️

Early stopping

Stop when val loss stops improving; restore the best checkpoint.

🪶

Smaller model

Fewer trainable parameters → less capacity to memorize.

🔄

Augmentation

Small rotations/shifts of training images — label-preserving, train only.

➕

More data / clean labels

More distinct examples, or repair the mislabeled ones — often the biggest win.

⚠️ No fix is guaranteed. On tiny 8×8 digits, too much augmentation can erase helpful detail and hurt.
Spotlight · Dropout vs Dropout2d

Drop activations, or whole channels

Standard Dropout randomly zeroes individual activations. Spatial Dropout2d zeroes entire feature-map channels in a CNN — better when neighbouring pixels are highly correlated.

Neither deletes or changes the filter weights — it only hides outputs during training, forcing the network not to rely on any single neuron or channel.
# MLP: hide activations
nn.Dropout(0.4)

# CNN: hide whole channels
nn.Dropout2d(0.2)

# L2 regularization via the optimizer
torch.optim.AdamW(params,
    lr=0.003, weight_decay=0.1)
Part IV · Transfer Learning as a Fix

Reuse features when data is scarce

Pretrain a CNN on the full 10-digit task, freeze its feature extractor, and attach a new Even-vs-Odd head trained on just 80 examples. With little data for the new task, reusing learned features can beat training from scratch.

# reuse the pretrained features, new 2-class head
transfer = SimpleCNN(num_classes=2)
transfer.features.load_state_dict(
    pretrained.features.state_dict())
# freeze the backbone
for p in transfer.features.parameters():
    p.requires_grad = False
# only the new head learns
One Honest Final Test

Select on validation, test once

①

Select

Pick the model with the lowest validation loss — never peek at test during selection.

②

Evaluate once

Run that single model on the untouched test set → the honest number (+ a confusion matrix).

③

Report

The test score is your real-world estimate. Reusing test data for tuning quietly inflates it.

✓ Golden rule: validation chooses, test confirms. Keep related images/patients/customers in the same split to avoid leakage.
Recap · Board Takeaway

Better data + sensible capacity + regularization

Overfitting = excellent fit to training-specific details, weaker generalization. We saw it in an MLP and a CNN on noisy digits, then closed the gap with dropout, weight decay, early stopping, smaller models, augmentation, more/cleaner data, and transfer learning — judging everything by validation loss and confirming once on test.

A low training loss does not guarantee real-world performance. Next: NLP → RNNs → Attention & Transformers.
