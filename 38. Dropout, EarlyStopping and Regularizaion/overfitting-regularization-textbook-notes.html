Overfitting, Dropout & Regularization

A neural network can memorize its training set — even wrong labels — and still fail on new data. This chapter defines overfitting and the generalization gap, then explains the full toolbox (dropout, Dropout2d, weight decay, early stopping, smaller models, augmentation, more/cleaner data, transfer learning) and how to evaluate honestly.

1.What Is Overfitting?

Overfitting = an excellent fit to training-specific details, with weaker generalization to unseen data. The model learns the quirks — and even the mistakes — of the training set instead of the real pattern.

low training loss ≠ good real-world performanceThe validation curve, not the training curve, reveals when generalization starts to deteriorate.

The three splits each have a distinct job: training updates the weights, validation chooses settings and checkpoints (without updating weights), and test is kept untouched until a single final evaluation.

Underfitting, overfitting and the capacity balance

Overfitting is one end of a spectrum; underfitting is the other. A model that is too simple (or too heavily regularized) can't even fit the training data — high error everywhere. A model that is too complex (or trained too long) fits the training data and its noise — low training error, high test error. The goal is the balanced middle: enough capacity to learn the real pattern, not so much that it memorizes.

Capacity knobs cut both ways. Dropout, weight decay and a smaller model all reduce effective capacity. A little fixes overfitting; too much causes underfitting. The discussion exercises at the end of this chapter ask you to feel exactly where that line sits.

2.The Experiment Design

To make overfitting visible on a CPU, the lab uses sklearn's load_digits() (1,797 images of 8×8 digits — no download) and rigs the data so memorization is obvious:

  • Tiny training set — 120 images (vs 800 for the "more data" run).
  • 25% corrupted training labels — a quarter of the training labels are flipped to wrong digits.
  • Clean validation & test — those labels stay correct, so they tell the truth.
The key insight: if a model reaches 100% accuracy against intentionally-wrong training labels, it is memorizing noise, not learning digits. More training cannot fix that — only better data or regularization can.

3.The Generalization Gap

As training proceeds, training accuracy climbs toward 100% while validation accuracy plateaus and then dips. The growing distance between them is the generalization gap — the visual signature of overfitting.

4.Dropout & Dropout2d

Dropout randomly zeroes individual activations during training (a probability p, e.g. 0.4), forcing the network not to rely on any single neuron. Spatial dropout (Dropout2d) zeroes entire feature-map channels in a CNN — more effective there because neighbouring pixels in a channel are highly correlated.

model.train() vs model.eval()

Dropout (and BatchNorm) behave differently in training and evaluation, so you must tell the model which mode it is in:

ModeCallDropout behaviour
Trainingmodel.train()ON — randomly zeroes activations so the net can't rely on any one neuron.
Evaluationmodel.eval()OFF — uses the full network for a deterministic, fair measurement.

In the lab, fit() calls model.train() at the start of each epoch, and evaluate() calls model.eval() before scoring. Forgetting eval() at evaluation time is a classic bug: your validation/test numbers become noisy and pessimistic because dropout is still randomly deleting activations. (Inference also wraps scoring in torch.inference_mode() to skip gradient tracking.)

5.Weight Decay (L2 Regularization)

Weight decay adds a penalty on large weights to the loss, discouraging the network from over-relying on any single feature. In PyTorch it's a single optimizer argument:

optimizer = torch.optim.AdamW(params, lr=0.003, weight_decay=0.1)
total loss = data loss + λ · Σ w²λ (the weight_decay) is small; a larger value pulls weights toward zero harder. AdamW decouples this penalty from the gradient step for cleaner regularization.

6.Early Stopping

Instead of training a fixed number of epochs, early stopping watches validation loss and stops when it has not improved for patience epochs — then restores the best checkpoint (not the last). This keeps the generalizing model and discards the memorizing one.

7.Capacity, Augmentation & Data

  • Smaller model — fewer trainable parameters means less capacity to memorize (small=True shrinks the hidden sizes).
  • Data augmentation — small label-preserving transforms (rotations ±8.6°, shifts) applied only to training images, via affine_grid + grid_sample.
  • More data / clean labels — more distinct examples, or repairing the mislabeled ones, is often the biggest win.
No fix is universal. On tiny 8×8 digits, too much augmentation can erase helpful detail and hurt. Always judge by validation loss in your setting, and change one thing at a time.

8.Transfer Learning as a Fix

When the new task has little data, reuse features from a related task. The lab pretrains a CNN on all 10 digits, freezes its feature extractor, attaches a new Even-vs-Odd 2-class head, and trains on just 80 examples — compared against training from scratch.

transfer = SimpleCNN(num_classes=2)
transfer.features.load_state_dict(pretrained.features.state_dict())   # reuse
for p in transfer.features.parameters():
    p.requires_grad = False     # freeze; only the 2-class head learns

Pretraining learns a useful representation; freezing keeps it fixed; the new head adapts. (See Class 37 for the full treatment.)

9.Honest Evaluation

  1. Select the model with the lowest validation loss — never peek at test during model selection.
  2. Evaluate once on the untouched test set → the honest accuracy, plus a confusion matrix to see which classes confuse.
Validation chooses; test confirms.Reusing the test set for tuning silently inflates your reported score. Keep related items in the same split to avoid leakage.

The whole idea, in one paragraph

Overfitting is an excellent fit to training-specific details with weaker generalization — a model can hit 100% on training data (even on deliberately wrong labels) yet fail on new data. You spot it as a widening generalization gap between training and validation curves, and you fight it with a toolbox: dropout / Dropout2d (hide activations or channels in training), weight decay (penalize big weights), early stopping (stop at best validation and restore that checkpoint), smaller models, augmentation and more/cleaner data, and transfer learning when data is scarce. Throughout, you judge by validation loss and confirm once on an untouched test set — because a low training loss never guarantees real-world performance.
