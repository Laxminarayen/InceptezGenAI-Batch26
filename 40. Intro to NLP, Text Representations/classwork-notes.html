Intro to NLP & Text Representations

We know how to turn an image into numbers — but how do you turn text into numbers a model can learn from? This session climbs the ladder of text representations: Bag of Words → Count Vectorizer → TF-IDF → n-grams → Word2Vec embeddings, each fixing a weakness of the last, ending with vectors that finally capture meaning.

Part I: What Is NLP?

NLP = Natural Language + Processing — run some kind of process over natural language. A natural language (Malayalam, English) is not a programming language (Python). Natural languages are:

  1. Organically developed,
  2. Evolved for a human community,
  3. Passed through generations, undergoing changes over time.

Properties of natural language

  1. Phonology → phonemes (sound units), e.g. the "dh" sound in father.
  2. Syntax → word order & sentence structure — the sequentially ordered placement of words (S-V-O, S-V-P).
  3. Lexicon → the linguistic collection of words.
Multiple nested dependencies. "Lammi likes to eat Italian food. He is very fond of this cuisine." Resolving "He" → Lammi and "this cuisine" → Italian food requires remembering earlier context. Language is not a bag of independent words — this is the core NLP challenge.

Part II: Revision — Where We Are

AI ⊃ ML ⊃ {Traditional ML, Deep Learning}; NLP spans across all of it (🟡 "you are here" in DL). In deep learning the feature representations are learned automatically via deep weighted affines:

  • Simple NN — a global representation: input layer → hidden (ReLU) → output ŷ; loss by task (MSE for regression, sigmoid+BCE for binary, categorical cross-entropy for multiclass).
  • CNN — a local / spatial representation based on sliding filters (3×3, stride).
  • Training loop — (1) loss calculation: predict on train(x), loss = lossfn(predict); (2) optimizer (SGD / Mini-batch / Full-batch / RMSProp / Adam): zero_grad() resets residuals, loss.backward() computes gradients; (3) optimizer.step() updates the weights.
Today's bridge: we now know how to represent an image as numbers (m × n × 3). How do we represent text as numbers?

Part III: Text Representations

(a) Bag of Words / One-Hot

Take the reviews, lowercase them, and remove stop words — highly frequent words that carry little standalone meaning (the, is, a, of). Collect the unique content words as columns, one row per sentence; each cell is 1 if the word appears, else 0.

Reviewmoviegoodwastetimeloved
"the movie is good"11000
"…a waste of time"10110
"loved the movie"10001

This converts text into a table that classical methods can consume: Linear/Logistic Regression, KNN, K-Means, a neural net.

Three disadvantages of Bag of Words

  1. Word order / meaning lost — "the movie was bad, the whole experience is a bad experience" — BoW does not take order into account.
  2. Frequency ignored — if a word is repeated many times it matters, but 0/1 can't tell once from many. (Needs dynamic weightage.)
  3. No contextual / semantic meaning — KING − MAN + WOMAN = QUEEN; relationships like royalty/rich aren't captured.

(b) Count Vectorizer (Term Frequency)

Addresses disadvantage #2. Each cell becomes the count of the word in the sentence, not just 0/1 — so repetition is captured.

Count Vectorizer = term frequencyIf a word is repeated in a sentence, it makes sense to weigh it more. But a word present a lot across the whole document set should be taken care of — that's the next step.

(c) TF-IDF (Term Frequency × Inverse Document Frequency)

TF matters when the whole document is not about that word. IDF gives a negative weightage to words frequent across the whole collection.

TF = (word count) ÷ (number of words in the sentence)
IDF = log( total documents ÷ documents in which the word occurs )
weight = TF × IDF A word appearing in every document → IDF = log(1) = 0 → its weight vanishes (acts like an automatic stop word). Rare, distinctive words get a high weight.

Worked example (reviews: "the movie is good" · "…a waste a waste of time" · "loved loved the movie"; 3 docs). "movie" is in all 3 → IDF = log(3/3) = 0, so its TF-IDF is 0 everywhere. Distinctive words score high: loved ≈ 0.73, waste ≈ 0.55, good ≈ 0.55.

n-grams

Add some word pairing: n=1 → single words {movie, time, loved, good, wasted}; n=2 → adjacent pairs {"movie good", "time wasted", …}. Captures a little local order.

Still missing semantics. One-hot, Count Vector, and TF-IDF all share one flaw: no paired association of meaning — no semantic meaning — and they rely on manual feature engineering.

Part IV: Word2Vec — Learning the Representation

Is there a method that understands deeper feature relations without feature engineering? Yes — use a neural network for representation learning. Instead of assigning vector values by hand, give the model sentences and a prediction task involving nearby words. The result is word embeddings.

Learn word predictions ⟹ learn word vectorsA word's numerical ID is arbitrary (cat = 1, dog = 2…); Word ID ≠ word meaning. The learned vector is what carries meaning.

Context window

The neighbouring words considered around a particular word. In "The cat [drinks] fresh milk" with IDs [the=5, cat=1, drinks=4, fresh=6, milk=7]:

  • Target word to predict: drinks (4)
  • Context words: the, cat, fresh, milk (5, 1, 6, 7)

Two architectures

ArchitectureIdeaIn / Out
CBOW
(Continuous Bag of Words)		Use the surrounding words to predict the centre word.X = [5,1,6,7] (context) → Y = 4 (target)
Skip-gramReverse it: use the centre word to predict the surrounding words.X = [4] (centre) → Y = [5,1,6,7] (context)

Where the vector comes from

Word2Vec = a shallow neural network + word IDs. The network's output (classification) layer has one neuron per vocabulary word (~70,000). But we don't want the prediction — we want the hidden layer. After training, remove the classification head; the learned hidden weights for each word are its embedding.

cat → a 128-dim vector (not a 70,000-dim one-hot)A dense, low-dimensional vector that captures the word's learned meaning — "it learns a numerical representation of words using the prediction pattern."
Semantic geometry (the payoff): similar words cluster — cat & dog near each other, car & bus in their own group; usage like "consume" pulls drank toward beverage contexts; and relationships become arithmetic (KING − MAN + WOMAN ≈ QUEEN). This is the semantic meaning BoW/TF-IDF never had.
