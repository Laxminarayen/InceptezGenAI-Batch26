Part I · Natural Language Processing

Run a process over human language

NLP = Natural Language + Processing. A natural language (Malayalam, English…) is not a programming language (Python). It is organically developed, evolved for a human community, and passed through generations, changing over time.

Where we are: AI ⊃ ML ⊃ Deep Learning — and NLP spans across all of them. Today we point deep learning at language.
Properties of language
Phonology — sounds (phonemes, e.g. the "dh" in father). Syntax — word order & sentence structure (S-V-O). Lexicon — the collection of words.
🚩 Multiple nested dependencies: "Lammi likes italian food. He is fond of this cuisine." Understanding "he" and "this cuisine" needs context from earlier — language is not independent words.
The Core Question

We can vectorize images. How about text?

🖼️

Image → numbers

A picture is already an m × n × 3 grid of pixel values. Easy to feed a network.

❓

Text → numbers?

"The movie is good" has no obvious numeric form. We must design a representation.

🎯

The goal

A representation a classifier (Logistic Reg, KNN, a neural net) can consume — ideally one that keeps meaning.

The plan: start simple (presence of words), then add frequency, then down-weight common words, then — finally — learn vectors that encode meaning.
Part II · Bag of Words (One-Hot)

Is each word present, yes or no?

Collect the unique words across all reviews (lowercased, with stop words removed), make one column per word and one row per sentence. Each cell is 1 if the word appears, else 0.

text → document-term matrix (0/1)Now classical models (Linear/Logistic Regression, KNN, K-Means, NN) can consume the table.
Stop words
Highly frequent words that carry little standalone meaning — the, is, a, of. We drop them so the vocabulary focuses on content.
✓ Simple, fast, and it turns messy text into a fixed-width numeric table.
Three Problems With Bag of Words

What the bag throws away

🔀

1 · Word order lost

"a bad experience, the whole thing" vs a good review can look similar — sequence & meaning are gone.

🔢

2 · Frequency ignored

A word repeated many times in a review matters — but 0/1 can't tell once from ten times.

🧠

3 · No semantics

KING − MAN + WOMAN = QUEEN is invisible. "royalty", "rich" relationships aren't captured at all.

The next representations fix these one by one: Count Vectorizer → problem 2, TF-IDF → problem 2 better, Word2Vec → problem 3.

Count Vectorizer & TF-IDF

Weight words by how telling they are

Count Vectorizer = term frequency — each cell becomes a count, fixing "once vs many". But a word common across every review (like "movie") isn't informative.

TF-IDF = TF × IDFTF = count ÷ words in the sentence.   IDF = log(total documents ÷ documents containing the word).
The IDF trick
A word in every document gets IDF = log(1) = 0, so its weight vanishes — it acts like an automatic stop word. Rare, distinctive words get a high weight.
✓ TF-IDF gives each word a dynamic weight: important where it's distinctive, discounted where it's everywhere.
n-grams & the Remaining Gap

Even TF-IDF is still missing meaning

n-grams add some word pairing: instead of single words (n=1: movie, time, good), use adjacent pairs (n=2: "movie good", "time wasted"). It captures a little local order…

🚩 …but no paired association of meaning: one-hot, count, and TF-IDF all still have no semantic meaning, and they lean on manual feature engineering.
The big question: is there a method that understands deeper feature relations — without feature engineering?
✓ Yes — use a neural network to learn the representation. That gives us word embeddings.
Part IV · Word2Vec — Representation Learning

Don't assign vectors — learn them

Instead of hand-coding numbers, give a model sentences and a prediction task involving nearby words. Solving "which word fits here?" forces it to learn useful word vectors as a side effect.

Learn word predictions ⟹ learn word vectorsA word's ID (cat = 1) is arbitrary — but the learned vector encodes its meaning.
Context window
The neighbouring words around a target. In "The cat [drinks] fresh milk", the target is drinks and the context is the, cat, fresh, milk.
Word ID ≠ word meaning. IDs just index the vocabulary; the vector learned for each ID is what carries meaning.
Two Architectures

CBOW vs Skip-gram

🎯

CBOW (Continuous Bag of Words)

Use the surrounding words to predict the centre word.

X = [the, cat, fresh, milk]
        ↓ (neural net)
Y = "drinks"   # context → target
🔁

Skip-gram

Reverse it: use the centre word to predict the surrounding words.

X = "drinks"
        ↓ (neural net)
Y = [the, cat, fresh, milk]  # target → context
Word2Vec = a shallow neural network + word IDs. Both setups train the same kind of small network to predict words from neighbours.
The Trick · Where the Vector Comes From

Train to classify, then remove the head

The network predicts a word out of the whole vocabulary (its output layer has ~70,000 neurons = vocab size). But we don't want the prediction — we want the hidden layer. After training, remove the classification head; the learned hidden weights for each word are its embedding.

cat → a 128-dim vector (not 70,000-dim)A dense, low-dimensional vector that captures the word's learned meaning.
✅ Dense & small: every word becomes ~128 numbers instead of a giant sparse one-hot.
It learns a numerical representation of words using the prediction pattern — exactly the "deeper feature relations without feature engineering" we wanted.
Why It's Magic · Semantic Geometry

Similar words cluster; meaning becomes arithmetic

🐱

Clusters form

cat and dog land near each other; car and bus form their own neighbourhood.

➕

Vector arithmetic

KING − MAN + WOMAN ≈ QUEEN — relationships become directions in the space.

🥤

Context captured

"consume" pulls drank near cat+beverage contexts — usage shapes position.

✓ Finally, a representation with semantic meaning — the thing BoW and TF-IDF could never give us.
Recap & What's Next

Words are now vectors

We climbed from Bag of Words (presence) → Count Vectorizer (frequency) → TF-IDF (dynamic weight) → Word2Vec (learned embeddings with CBOW / Skip-gram). Each fixed a flaw of the last; embeddings finally capture meaning as geometry.

Open question: embeddings give each word a vector, but how do we represent a word in a sequence, where order matters? Next: RNNs & LSTMs.
